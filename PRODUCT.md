## Platform

web

## Users

Кабинет — только для сотрудников ОСИ ЖК «Мунар Тау»: управляющие (администратор, заместитель, председатель), техадминистратор, исполнители (просмотр своих заданий). Возрастных и особых требований к кабинету нет — решение пользователя 23.10.2026. Жители и исполнители работают в Telegram-ботах (`@munar_tau_user_bot`, `@munar_tau_worker_bot`), их интерфейсы — вне области кабинета.

## Product Purpose

Система управления ОСИ жилого комплекса «Мунар Тау» (~45 трёхэтажных домов, ~600 квартир): обращения жителей с жизненным циклом, задания исполнителям, общие аварии, платные работы с сверкой оплат Kaspi, публикации и документы, опросы, отчётность, декларативные регламенты времени, журнал действий. Заменяет процесс «всё через WhatsApp» на управляемый: номера, состояния, сроки, эскалации. Кабинет — рабочее место сотрудников: обработка обращений, управление исполнителями и настройка процессов.

## Positioning

Управляемый процесс вместо мессенджера: у каждого обращения — номер, состояние, срок и ответственная роль; права проверяются серверным PDP при каждом запросе, все действия журналируются. Регламенты времени декларативные (TIM-02), эскалации автоматические.

## Capabilities and Constraints

- Стек закреплён ADR и не меняется без нового ADR: Vite + React 18 + Refine v4 + Ant Design 5, статика на Cloudflare Pages без серверных функций (ADR-002)
- Секреты в браузере запрещены; в статической сборке только publishable-значения
- Терминология строго по глоссарию HLD: обращение, задание, общая работа, инцидент, регламент, помещение, связь, эмуляция; слово «Управляющий» в интерфейсе не используется (UI-01)
- Структура страниц — общий `PageLayout`: заголовок с переключателем вида → управляющие кнопки → фильтры → рабочая область
- Все таблицы — через `ConfigurableTable`; карточки процессов — `ProcessOverview`/`ProcessActions`/`DetailSection`/`CardDrawer`
- Кнопок перечитывания «Обновить» нет — `usePageRefresh` (раз в минуту, при возврате во вкладку, повторном выборе меню)
- Два языка интерфейса ru/kk; локаль AntD — ru_RU
- Канбан-доски — только просмотр, без drag-and-drop (FSM-переходы требуют причин и ролей)

## Product Principles

1. Процесс ведёт интерфейс: пользователь всегда видит состояние, ожидаемого участника, срок и следующий шаг (ProcessOverview, одно основное действие)
2. Точность вместо украшений: номера, состояния, сроки и причины переходов важнее декора; режим Operate — сканируемость и консистентность
3. Одни правила для бота и кабинета: терминология, данные, права и аудит общие
4. Право на действие проверяется сервером — UI не показывает недоступные действия и не обещает обход PDP
