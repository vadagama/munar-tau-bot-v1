# Спецификация VS-8: `reports`

Дата: 23.10.2026. Статус: согласовано пользователем 23.10.2026 сообщением «Делай», включая
предложения раздела «Решения для согласования».
Модуль [карты](VS8-CAPABILITY-MAP.md).
Стек, команды, структура, стиль, проверки и границы — [общая часть](SPEC-vs8-conventions.md).

## Цель и аудитории

REP-01–06, RAT-04, KPI-01–02: показать работу, сроки и результаты в разрешённой
области; выдавать безопасный Excel через очередь. Отчёты не открывают
финансовую аудиторию, жалобы, внутренние файлы или чужую переписку.

| Получатель | Содержание |
| --- | --- |
| Исполнитель REP-01 | Свои назначения, визиты, сроки, просрочки, доработки и выполненное за период |
| Управляющий REP-02 | Новые, без исполнителя, непринятые назначения, непрочитанные входящие, близкие сроки, просрочки, доработки, проверки; переходы к доступным объектам |
| Председатель REP-03 | Поступило, выполнено, открыто, просрочено, ответ, возвраты, загрузка по ОСИ/домам/периоду; отдельно отмены, отказы, административные закрытия и подтверждения автора |
| Житель REP-04 | Только опубликованные работы/планы и разрешённые сводки по дому/ОСИ, без чужих карточек и ПД |

Тестовые персоны/объекты исключаются из реальных показателей и KPI;
эмуляция показывает отдельный тестовый набор. Счётчики, строки и экспорт
используют одну область PDP. Адресные обращения без building_id видны
в общей очереди управляющих по ADR-015; фильтр конкретного дома их не включает.

## Контракт формул — предложения по OQ-15

Интервал `[from, to)` задаётся датами Asia/Almaty, превращается в абсолютные
границы на сервере. В ответе фиксируются границы, часовой пояс и `as_of`.
Предлагается хранить историю переходов и таймеров, вычислять снимки и потоки
раздельно; отсутствие исторического события возвращать как отсутствие данных.

| Показатель | Предлагаемое определение |
| --- | --- |
| Поступило | Уникальные обращения с регистрацией в интервале |
| Выполнено | Уникальные обращения с окончательным закрытием в интервале; способ закрытия показывается отдельно |
| Открыто | Срез на `as_of`: зарегистрированные до этой границы, не закрытые/отменённые/отклонённые на неё |
| Просрочено | Открытые на `as_of` с хотя бы одним применимым нарушенным сроком; несколько таймеров не удваивают обращение |
| Первый ответ | Время от регистрации до первого содержательного ответа сотрудника аудитории resident; автоуведомление/назначение/внутренняя заметка не считаются; выборка по дате регистрации, наблюдение до `as_of` |
| Агрегаты первого ответа | Среднее и медиана по имеющим ответ, рядом размер выборки и количество без ответа; календарные и рабочие минуты отдельно |
| Возвраты | Число событий возврата на доработку в интервале и отдельно число уникальных обращений с возвратом |
| Загрузка | На `as_of` число незавершённых назначенных заданий по сотруднику; выполненные за период отдельно по времени приёмки отчёта, без балла производительности |
| Близкий срок | Непросроченный активный таймер внутри окна предупреждения своей версии регламента; без настроенного окна не изобретать порог |

Для открытых обращений календарный возраст — `as_of - registered_at`.
Для закрытых — `closed_at - registered_at`; он не растёт после закрытия.
Рабочая длительность — пересечение интервала с графиком применимого
норматива и разрешёнными интервалами активности; версия правила сохраняется.
Для аварий используется 24/7. Если таймеров разных назначений несколько,
их длительности показываются по назначению, не складываются в один «возраст».

Предлагаемые циклы REP-06: первый начинается регистрацией; последующий —
возвратом на доработку; конец — закрытие либо следующая граница возврата.
Ожидание подтверждения — отдельный интервал внутри цикла. Если обращение
возвращено из ожидания до закрытия, предыдущий цикл завершается этим возвратом.
Прежние закрытия и циклы сохраняются; общий окончательный итог определяется
последним закрытием после доработок. При новом цикле прежняя оценка не
считается актуальной для нового результата.

## Уже согласованные KPI и рейтинг

RAT-04: число заявок с актуальной оценкой среди закрытых с подтверждением автора
в интервале / число таких закрытых × 100%. Отказы, отмены и административные
закрытия исключены; пустой знаменатель даёт `null` («Нет данных»), а не 0%.

KPI-01: уникальные подтверждённые пользователи с действующей связью,
включая нежилые объекты и сотрудников-жителей; пилот включён, тестовые,
предварительные и чисто служебные исключены. Предлагается показывать
срез на дату наблюдения; достижение цели в периоде фиксировать отдельным
датированным снимком, не теряя факт при последующем прекращении связи.

KPI-02: уникальные реальные обращения после общего запуска, окончательно
подтверждённые автором внутри периода; пилот, тест, отказы, отмены и
административные закрытия исключены. Возврат требует повторного подтверждения.

Период KPI — три календарных месяца по Asia/Almaty от 00:00 даты запуска,
конечная граница исключена. Предлагается при отсутствующей конечной дате
использовать последний день конечного месяца (31 января → 30 апреля 00:00).
Дата общего запуска задаётся явно; без неё KPI показывается как ненастроенный.

## API, экспорт и интерфейс

LLD-03: `GET /v1/reports/requests`, `/tasks`, `/incidents`, `/payments`;
`POST /v1/reports/export`; `GET /v1/reports/exports/{id}`.
Финансовый отчёт при отсутствии VS-6 сообщает недоступность источника,
не выдаёт нулевые фиктивные показатели.
Фильтры: период, дома, исполнитель в разрешённой области, статус;
DTO разделяет `flows`, `snapshot`, `durations`, `sample_sizes`, `as_of`.

Экспорт для administrator/chairman: очередь со снимком фильтров, области,
инициатора и границы данных; состояния pending/running/ready/failed.
Excel содержит номера, категории, статусы, сроки, результаты;
без телефонов, переписки, вложений и индивидуальных ответов опросов.
Строки, похожие на формулы, записываются как текст. Имя исполнителя — только
при разрешённой служебной аудитории, без лишних персональных полей.

Права повторно проверяются перед формированием и скачиванием. При потере
исходной области задание завершается отказом доступа, а не выдаёт прежний
файл либо молча усечённый отчёт. Готовый файл приватный, ссылка выдаётся
создателю после PDP; повтор задачи не создаёт повторной бизнес-операции.
Аудит фиксирует вид/период/область/результат, не содержимое строк.

Кабинет: ролевые панели, фильтры, различимые календарные/рабочие длительности,
размеры выборок и очередь экспорта. Бот сотрудника: «Моя работа» и доступные
показатели, переходы к объектам. Бот жителя: опубликованные работы/планы
дома/ОСИ через общую аудиторию публикаций. Общая управленческая сводка
не становится публичной от выбора жителем дома.

## Приёмка и проверки

- Fixtures с разными датами регистрации/закрытия различают поток и срез,
  пустую выборку, отмену, административное закрытие и подтверждение автора.
- График, ночь, авария 24/7, смена версии правила, два цикла доработки и
  ожидание подтверждения дают раздельные воспроизводимые длительности.
- KPI дедуплицирует помещения и роли, включает нежилые объекты/пилотных
  пользователей, исключает тест и пилотные обращения; проверена граница месяца.
- Чужая область, жалоба, финансовые данные и переписка недоступны через
  счётчики, CSV/XLSX, карточку задания экспорта и URL файла.
- Очередь выдерживает повтор и отзыв роли между постановкой/выполнением/
  скачиванием; файл Excel открывается и содержит только разрешённые колонки.
- При отсутствии VS-6 нет фиктивного отчёта оплат; REP-04 раскрывает только
  явно опубликованные данные.

Vitest с фиксированным временем проверяет формулы, SQL-интеграция —
историю/области/очередь, ExcelJS читает сформированный файл для сверки,
браузер проверяет фильтры, отсутствие данных, переходы и экспорт.

## Решения для согласования

Таблица формул, границы циклов, определение первого ответа, состав агрегатов,
срез/фиксация достижения KPI-01 и правило конца месяца являются предложениями.
Они закрывают часть OQ-15 только после явного согласования; исторические
события, которых нет, нельзя восстановить вымышленными значениями.
