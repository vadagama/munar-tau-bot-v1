# Сиды (справочные данные)

Сиды применяются после соответствующих миграций и требуют согласования значений
(гейты LLD-05, раздел 2).

| Файл | Содержание | Срез / гейт |
| --- | --- | --- |
| `identity_dev.sql` | Председатель, техадминистратор, дома-каркас, тестовые персоны эмуляции | VS-1 |
| `request_categories.sql` | Категории обращений (OQ-02) | VS-3, гейт «категории обращений» |
| `time_rules.sql` | Стартовый реестр правил TIM (значения согласованы 16.10.2026 — LLD-02 §9) | VS-5 |
| `service_catalog.sql` | Каталог платных услуг (OQ-09) | VS-6, гейт «финансовые правила» |

Правило (LLD-05 §2): процесс не включается с пустым правилом — сид обязателен
до включения соответствующего процесса.

## Привязка supabase_user_id (VS-1, точка О-1)

Профиль в `profile` связывается с пользователем Supabase Auth по
`supabase_user_id` = claim `sub` JWT. Пока привязки нет, вход даёт 401
`NO_PROFILE` — вход не выдаёт роль (AUTH-01).

Порядок привязки:

1. Примените миграции (`npm run` см. AGENTS.md → «Миграции БД»), затем сид
   `identity_dev.sql` (идемпотентен).
2. Выполните вход в кабинет через Telegram — Supabase Auth создаст пользователя
   (`auth.users`). Вход вернёт ошибку «NO_PROFILE» — это ожидаемо.
3. Найдите `sub` нового пользователя (id в `auth.users`):

   ```sql
   select id, email, phone, created_at from auth.users order by created_at desc limit 5;
   ```

4. Привяжите профиль и при необходимости замените справочные ФИО/телефон:

   ```sql
   -- Председатель
   update profile set supabase_user_id = '<SUB ИЗ ШАГА 3>'
   where telegram_user_id = 900000000001;

   -- Технический администратор
   update profile set supabase_user_id = '<SUB ВТОРОГО ПОЛЬЗОВАТЕЛЯ>'
   where telegram_user_id = 900000000002;
   ```

   Уникальный частичный индекс `profile_supabase_active_uq` допускает только
   один активный профиль на пользователя.

   Привязка входа не меняет `telegram_user_id` бота: заглушки остаются в
   зарезервированном диапазоне ≥ 900000000000 и обязаны быть `is_test`
   (CHECK `profile_placeholder_telegram_id_test`), поэтому их уведомления не
   уходят в реальный Telegram. Чтобы председатель/техадмин получали
   уведомления в Telegram, заведите им персоны через кабинет и привяжите
   реальные Telegram-аккаунты, затем передайте им роли.

5. Повторите вход: `/v1/meta/me` вернёт роли и пределы сеанса. Роли
   тестовым персонам эмуляции назначает председатель через кабинет
   (POST `/v1/admin/assignments`).

Персональные данные в сиде — справочные placeholder-значения; при переводе на
реальные данные замените ФИО и телефоны (или заведите персоны через кабинет).
