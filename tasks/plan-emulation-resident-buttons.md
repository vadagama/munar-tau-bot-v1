# Эмуляция жителя и кнопок бота

Основание: запрос пользователя от 19.10.2026, HLD §10.8, ADR-003/010/011, REG, REQ, WRK, NTF и AUD-01.

## Объём и приёмка

- В перечне персон роль «Житель» означает отсутствие служебных назначений. Доступен фильтр по этой роли. Создание тестовой персоны не выдаёт служебных полномочий и не создаёт подтверждённую связь с помещением.
- Общие сценарии возвращают текст и inline-кнопки, симулятор сохраняет ряды и подписи. Нажатие отправляет `data` той же бизнес-логике, которая обрабатывает текстовую команду, с обычными проверками PDP и аудитом.
- Постоянное меню использует общие функции `residentMenu`/`workerMenu`, язык профиля и актуальные переопределения каталога. Команда меню выбирает нужный сценарий; следующий текст продолжает его. Старые кнопки истории сохраняют исходный сценарий.
- Поле API `reply` остаётся строкой; `buttons` и `menu` добавлены без изменения прежнего контракта. В меню дополнительно передаётся `scenario`.
- Ошибка отправки сохраняет историю и введённый текст; при отправке кнопки блокируются. Текст ответа выводится через React без вставки произвольного HTML.

## Проверка

- Модульные тесты ядра: перенос кнопок через сервис, русское/казахское меню, переопределения каталога, меню сотрудника.
- Тесты кабинета: фильтр жителя, отключённый симулятор, нажатие inline-кнопки и переход меню с продолжением сценария.
- Deno: API под тестовой персоной без служебной роли возвращает текст, кнопки и меню; сохраняются проверки отсутствующего сеанса и неизвестного сценария.
- Браузер: реальная страница на локальных фикстурах API/идентичности, нажатия кнопок и ширины 320/768/1024/1440. Подключение к рабочим данным не выполнялось.
- Общие проверки: Vitest, typecheck, lint, сборка кабинета, secret-scan, Deno check/lint/test. Интеграционные тесты к БД не запускались согласно временному правилу проекта.

Публикация: необходимы новая сборка кабинета и деплой функции `api`; изменений схемы БД нет.

## Исправление маршрутизации команд (19.10.2026)

Регрессия: при выбранном сценарии «Обращения» команда `/register` попадала
в шаг выбора помещения и возвращала «Выберите номер из списка. /objects» без
кнопок регистрации. Сервер теперь выбирает сценарий по явной команде, используя
реестры команд общих модулей; обычный ответ продолжает выбранный сценарий.
Кабинет сохраняет возвращённый `scenario_id` для продолжения диалога и кнопок
под ответом. Добавлены регрессионные тесты сервиса и кабинета, воспроизводившие
ошибку до исправления. Проверки: Vitest, Deno check/lint/test, typecheck, lint,
сборка и secret-scan; интеграционные тесты к БД не запускались.

## Быстрое переключение ролей в шапке (19.10.2026)

- Только при активной эмуляции слева от «Выйти» отображается список ролей,
  сгруппированный по фактическим назначениям тестовых персон; отсутствие
  назначений — «Житель». При нескольких персонах видны их имена. Выбор
  переключает всю персону со всеми её полномочиями, а не назначает роль.
- Список загружается через существующий `GET /v1/emulation/persons` с общим
  `usePageRefresh`. Смена выполняется через `POST /v1/emulation/sessions` с
  проверкой реального актора, закрытием прежнего сеанса и аудитом (AUD-01,
  HLD §10.8). После успеха — полная загрузка главной страницы под новой персоной.
- Во время запроса выбор заблокирован; ошибка сохраняет текущую персону и
  показывается рядом. Вне эмуляции нет списка и запросов за персонами.
- Приёмка: 146 тестов кабинета; typecheck, lint, сборка, secret-scan.
  В браузере на локальных фикстурах проверены переключение житель → исполнитель,
  отсутствие списка вне эмуляции, отсутствие горизонтального переполнения
  при ширинах 320/768/1024/1440. Интеграционные тесты к БД не запускались.

Для публикации этого дополнения нужна только новая сборка кабинета.
