# UX бота — срез A «Быстрые победы» и срез B «Кнопки и один язык»

Срез A: ветка `feature/bot-ux-quick-wins` (объединён). Срез B: ветка `feature/bot-ux-buttons-language`.
Источники: предложения по UX бота от 17.10.2026; бизнес-сценарии REQ/WRK/REG не меняются — меняется только подача. Ограничения: AUTH-03 (привилегированных действий в боте по-прежнему нет), ADR-003 (общие модули бота и кабинета), HLD §19 (тесты), паритет бота и симулятора (один ScenarioRegistry).

## Цели

Поднять читаемость и предсказуемость бота без изменения бизнес-правил:

1. Меню команд Telegram (`setMyCommands`) и описание бота — скрипт настройки среды.
2. HTML-разметка ответов (жирные заголовки, моноширинные команды), отключение превью ссылок; доставка по-прежнему через устойчивую очередь.
3. Человекочитаемые даты (часовой пояс Алматы, детерминированный форматтер без зависимости от ICU) вместо ISO-строк.
4. Номер строки списка вместо UUID в домене регистрации (объекты, анкеты на подтверждение, выданные доступы, статус анкет); полные UUID по-прежнему принимаются — интеграционные тесты и внешние сценарии не ломаются.
5. Дружелюбные тексты ошибок с подсказкой следующего шага: по коду `ApiError`; кастомные сообщения сценариев сохраняются как есть.
6. Контекстные подсказки действий вместо полной простыни HELP в каждой реплике; полная справка — по `/help`.

## Ограничения и совместимость

- Паритет симулятора: все действия остаются доступны текстом; кнопки не вводились. HTML-разметка видна в интерфейсе эмуляции как теги — косметика, допустимо для среза A.
- Очередь уведомлений, идемпотентность и структура БД не меняются — меняется только payload отправки и тексты.
- Язык: остаёмся на сдвоенных текстах «ru / kk»; переключение на один язык по `profile.language` (инфраструктура уже есть в `notificationStep`) — срез B.
- Команды принимают и номер строки последнего списка, и полный UUID; префикс UUID — если совпадение уникально.

## Срез B «Кнопки и один язык» (выполнен)

- `bot/keyboard.ts`: `InlineButton`, `BotReply` (строка или текст + ряды inline-кнопок), `replyText()` (эмуляция видит только текст), `btn()` (callback_data длиннее 64 байт — ошибка программиста), `inlineMarkup()`, `menuMarkup()`.
- `callback_data` кнопки — точная текстовая команда («/confirm З-26-1 2», номер строки списка): webhook превращает `callback_query` в синтетический текстовый шаг, паритет с текстом по построению, PDP и аудит общие.
- Кнопки: выбор языка анкеты, помещение/тип/роль регистрации, согласие («да»), решения собственника (`/approve`), выбор обращения/задания из списка, подтверждение результата с версией, оценка 1–5, пагинация списка, действия по состоянию задания, отправка черновика и отчёта. Причина/описание/свободный текст — только вводом текста.
- Reply-клавиатура главных действий прикрепляется к ответам на `/start` и `/help` (житель: `/newrequest`, `/requests`, `/status`, `/objects`, `/notifications`, `/help`; сотрудник: `/tasks`, `/help`), клавиатура постоянная.
- Один язык по `profile.language` (фолбэк ru) вместо сдвоенных «ru / kk»: сценарии регистрации, обращений, заданий, инцидентов, уведомлений, справка и ошибки; в диалоге регистрации до выбора языка действует язык профиля. Уведомления вне бота сохраняют сдвоенный вид (`labelCombined`).
- Разметка клавиатуры хранится на уведомлении (`notification.reply_markup jsonb`, миграция `20261017140000_bot_ux_buttons.sql`), прикрепляется к последней части разрезанного сообщения; каскад отправки: HTML + разметка → без parse_mode с разметкой → без разметки (повтор только при 400). `answerCallbackQuery` в webhook — best-effort.
- Следствия одного языка: в отчёте исполнителя «жоқ» признаётся синонимом «нет» (ограничения/причина отсутствия доказательства) — иначе подсказка на казахском вводила бы пользователя в заблуждение.
