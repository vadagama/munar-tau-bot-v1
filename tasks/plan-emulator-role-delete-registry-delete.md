# Удаление ролей в эмуляторе и удаление зданий/помещений

Основание: запрос пользователя от 21.10.2026 («добавь возможность удалять роли в эмуляторе; для всех справочников в помещениях — возможность удаления: дома, квартиры и т.д.»), HLD §10.8, LLD-03 §3.3/§3.16, ADR-003, AUD-01, ROL-04.

## Объём и решения

- Страница эмуляции: роль тестовой персоны снимается крестиком на теге в таблице персон. Обязательная причина (модальное окно), после успеха — перечитывание списка и идентичности. Выдача ролей остаётся у председателя; переключатель ролей в шапке не менялся.
- Новый PDP-акшен `emulation.person.role.revoke` (не privileged, только tech_admin) и маршрут `POST /v1/emulation/assignments/{id}/revoke` с телом `{reason}`. POST вместо DELETE: тело запроса с причиной читается только у методов с содержимым. PDP оценивается реальным актором (`evaluateAs: "real"`).
- Сервис `revokeTestPersonRole` (домен эмуляции): только реальный техадмин вне эмуляции (защита в глубину), только активное назначение, только is_test-персона. При сокращении набора ролей сеансы персоны закрываются (консистентно с формой «Сотрудники»), ставится уведомление `notices.staff.roles_changed` (для тестовой персоны — канал симулятора), аудит `emulation.person.role.revoke` с before/after наборов ролей и причиной.
- Удаление справочников — жёсткий DELETE с каскадом по прецеденту миграции `remove_parking_buildings` (на демостенде почти у каждой квартиры есть связи, поэтому guarded-удаление было бы бесполезно): у помещения удаляются связи, приглашения и анкеты (FK обязательны), обращения сохраняются без привязки (`premises_id = null`); у здания дополнительно отвязываются обращения по зданию, удаляются дежурства, области инцидентов/публикаций/сотрудников.
- Здание: только председатель, в эмуляции запрещено (зеркалит правку зданий); при активных аварийных сигналах удаление запрещено (журнал аварий append-only). Помещение: обычные права `registry.write` по области дома и тестовому домену, доступно в эмуляции. Лица и связи этим маршрутом не удаляются (у связей есть процедура прекращения, лица — люди с историей).
- Маршруты `DELETE /v1/registry/buildings/{id}` и `DELETE /v1/registry/premises/{id}` (акшен `registry.write`), аудит `registry.buildings.delete` / `registry.premises.delete` с подсчётами каскада.
- Кабинет: в «Помещениях» кнопка «Удалить» с опасным Popconfirm, текст которого называет последствия (связи/приглашения/анкеты удаляются, обращения сохраняются без привязки; для здания — запрет при аварийных сигналах). Ошибки — в общей ошибке страницы.

## Проверка

- Ядро (Vitest): снятие роли — успех, аудит, outbox-уведомление, несколько ролей, не-тестовая персона (FORBIDDEN), неактивная персона, повторный отзыв, пустая причина, отзыв под эмуляцией; удаление помещения/здания — последовательность SQL, подсчёты, guard аварийных сигналов, запрет не-председателю и в эмуляции, NOT_FOUND/чужой тестовый домен/вне области, запрет для лиц и связей.
- Deno: техадмин снимает роль (200, отзыв, аудит, outbox), 400 без причины, 403 не-техадина; маршруты удаления зарегистрированы с верными акшенами, у лиц/связей маршрута нет.
- Кабинет (Vitest): модалка причины с обязательным полем, вызов revoke, обновление идентичности, показ ошибки; Popconfirm с последствиями, DELETE-вызов, ошибка удаления, отсутствие кнопки у жителей.
- Общие проверки: Vitest (628 ядро + 168 кабинет), Deno check/lint/test (55), typecheck, lint, сборка кабинета, secret-scan. Интеграционные тесты к БД не запускались согласно временному правилу проекта.

Публикация: нужны новая сборка кабинета и деплой функции `api`; изменений схемы БД нет.
