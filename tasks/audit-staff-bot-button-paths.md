# Кнопочные пути ботов: инвентаризация реализации

21.10.2026. Основание: SBR-13/14/15, ADR-017. Это аудит кода и стандартного
каталога; активные версии Frankfurt прочитаны отдельно в read-only транзакции.

| Раздел | Точки входа и действия |
| --- | --- |
| Регистрация и связи | Справка → регистрация/профиль/исправление/удаление/помещения/добавление/приглашения/доступы; прежние inline-решения сохранены |
| Обращения жителя | Создание и черновик; номер-ссылка списка; сообщение; подтверждение/возврат/отмена/оспаривание/повторное открытие; общий доступ с выбором человека; оценка с необязательным комментарием; следующий отчёт кнопкой |
| Обращения сотрудника | Очереди/фильтры/номер; карточка и страницы материалов; явное чтение; REQ-переходы, свойства, задание, исполнитель, отчёт и приёмка; публичный ответ и внутренняя заметка |
| Исполнение | Приём/отказ/старт/отчёт/причина паузы/найденная проблема; выбор сохранённого доказательства или причина отсутствия |
| Визиты | Предложение даты и пояснения с проверкой версии; согласование/заявление о неявке жителем; заявление об отсутствии доступа исполнителем |
| Аварии и публикации | Списки и карточки; контакты по дому; сигнал из обращения/задания; принятие сигнала; проблема после опубликованных работ |
| Настройки | Категория → допустимый режим; отдельные кнопки языка; mandatory-ограничения остаются в домене |

Общие ответы получают кнопки выхода через `navigationReply`. Справка содержит
контекст и входы в разделы. Свободный ввод — содержательные поля, а не варианты
меню. Числа/старые ручные команды остаются совместимыми.

Большие списки обращений содержат ссылки `req_`/`sreq_`; служебные связанные
задания — `stsk_`. Собственные ссылки симулятор отправляет в общий сценарий.
Сторонние ссылки не исполняются как команды. Ссылки не заменяют серверный PDP.

В текстовых формах и формах визитов медиа не публикуется в ранее открытую
карточку. Бот предлагает вернуться в карточку и прикрепить файл там. Служебные
answer/note имеют отдельный compose с отложенной отправкой после сохранения.

Стандартные тела ru/kk проверяет `templates/button-audit.test.ts`; дополнительные
проверки — native-input, visits, notifications, incidents-input, request-files,
registration-task-messages и inbound. Исторические подписи reply-меню остаются
в маршрутизации; актуальные и старые подписи проверяет `validateMenuLabels`.

Проверка переопределений перед выпуском, из `source/`:

```sh
deno run --env-file=.env.local --allow-env --allow-net tools/scripts/audit-bot-button-templates.ts
```

Нужен `DATABASE_URL` нужной среды; первым аргументом можно явно выбрать
SUPABASE_DB_URL или NEW_DATABASE_URL. Фактический запуск для Frankfurt:

```sh
deno run --env-file=.env.migration --allow-env --allow-net tools/scripts/audit-bot-button-templates.ts NEW_DATABASE_URL
```

Результат: `compatible=true`, `registeredTemplates=0`, `customOverrides=0`,
`issues=[]`. Пользовательских версий пока нет; применяется стандартный каталог.
Это не изменяет таблицы, тексты и историю версий.

Скрипт открывает read-only транзакцию,
показывает только ключ/язык/тип несоответствия. Он не меняет историю и не печатает
тексты или секреты. Найденные версии исправляются обычным редактором шаблонов:
оба языка, причина и действующий автор; сброс/откат создаёт новую версию.
Аудит требуется повторить перед выпуском, если после этой проверки изменятся версии шаблонов.
