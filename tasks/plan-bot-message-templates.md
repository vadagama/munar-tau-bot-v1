# Шаблоны сообщений Telegram-ботов

Ветка: `feature/bot-message-templates`, база: актуальный `origin/main`. PR в `main` — мерж после одобрения владельца.
Основания: спецификация — [docs/specs/bot-message-templates.md](../docs/specs/bot-message-templates.md), намерение — [docs/intent/bot-message-templates.md](../docs/intent/bot-message-templates.md). Решения по открытым вопросам подтверждены владельцем 2026-10-18 (откат = новая версия-копия; оба языка обязательны; тестовая отправка — вне срезов).
Задачи ведутся в этом файле (конвенция срезов проекта).

## Основания и границы

Источники: спецификация §2–§16; AGENTS.md (конвенции: общие модули, идемпотентность, `$n::text::jsonb`, privileged = кабинет-only, аудиторские записи); ADR-003/009.

Сохраняется без изменений: бизнес-правила, FSM, PDP-разрешения операций, аудитория данных, каскад доставки Telegram (HTML → без разметки), разрез длинных сообщений, дедупликация webhook, симулятор/эмуляция. Не входят: подписи кнопок, описания команд меню, словари-подписи (`stateLabels` и др.), `public_text` инцидентов.

Миграция БД — аддитивная, идемпотентная, проверяется на Sydney (`npm run db:push`); демонстрационный стенд Frankfurt этим PR не обновляется. Интеграционные тесты не запускать без явного запроса владельца (`RUN_INTEGRATION_TESTS=1`).

Ключевой принцип переноса: дефолт ключа в каталоге — точная копия текущего текста (golden-тесты охраняют); без переопределения поведение байтово совпадает с прежним.

## Риски и меры

| Риск | Влияние | Мера |
| --- | --- | --- |
| Регрессия в 136 местах механического переноса | Высокое | Golden-тесты (дефолт == прежний литерал) на каждый файл; перенос по одному файлу с проверками; финальный grep-барьер |
| Битый HTML от администратора ломает отправку | Среднее | Валидация белого списка и баланса при сохранении + существующий каскад доставки (400 → без parse_mode) |
| Рассинхрон каталога и БД (ключ удалён из кода) | Низкое | Резолвер игнорирует неизвестные ключи; список в кабинете строится от каталога кода |
| Старые payload'и outbox при деплое между версиями | Среднее | Обратная совместимость в `dispatchNotices` + unit-тест двух форматов |
| Конфликты с параллельными ветками (VS-5/VS-7) | Среднее | Ветка от свежего main; перенос текстов только там, где строка не меняется в чужих PR; ребейз перед PR |
| Лишняя нагрузка на БД (SELECT переопределений) | Низкое | Таблица десятков строк, один запрос на вебхук/тик; без кэша между вызовами (требование свежести правки) |
