- [x] Вычисление состояния общей работы без автоматического завершения; отменённое обязательное задание блокирует готовность, возврат возобновляет работу.
- [x] Проверки WRK-16: выполненный объём, время, результат, подтверждённые файлы, объяснение отсутствующего доказательства и отдельное обоснованное решение администратора.
- [x] Модульные тесты чистых правил (45 сценариев), lint и typecheck.
- [x] Схема хранения VS-4; транзакционные создание/назначение/принятие/отказ/старт/пауза/переназначение с PDP, version/409, append-only историей, идемпотентностью и устойчивыми уведомлениями.
- [x] API и очередь кабинета для этих операций; проверка принятия в Chrome на ширинах 320/768/1024/1440, компонентные тесты доступа.
- [ ] Подключение отчётов/доказательств, визитов, общей работы, шаблонов и бота; разблокировка ADR-006 после полного контура.

## Порядок реализации и проверки

- [x] Миграции: `task`, `task_log`, `task_report`, `visit`, `common_work`, `common_work_request`, `job_template` (LLD-02 §4); RLS-заслон; идемпотентно.
- [ ] Общий домен tasks (бот/кабинет/API по одним сервисам): FSM задания по модели процессов §5 — назначение, принятие/отказ с причиной (WRK-02), старт с условиями и зависимостями (WRK-11), приостановка с возвратом в записанное состояние и отдельным событием «Нет доступа», отчёт с версиями и обязательными доказательствами (WRK-16), приёмка/доработка/возврат после приёмки, переназначение с сохранением выполненного объёма, отмена обязательного задания с заменой; version/409; история назначений и переходов в `task_log` (FLOW-01).
- [ ] Общая работа: агрегированные состояния «Запланирована / Выполняется / На проверке / Завершена / Отменена», связывание обращений (WRK-10–12), персональная приёмка каждого обращения через снимки VS-3 (модель процессов §7); возврат задания возобновляет работу с сохранением прежней даты завершения; отмена общей работы не отменяет обращения автоматически; отмена/отказ WRK-13–14 — после начала работ только через администратора, отмена одного обращения не останавливает работу по другим заявителям.
- [ ] Визиты WRK-03–05: предложение и согласование даты/интервала автором или совместным участником, «Нет доступа» и «Исполнитель не пришёл» — отдельные события, договорённости сохраняются.
- [ ] Шаблоны JOB-01–06: чек-листы и обязательность фото, версии шаблонов — действующие запуски живут прежней версией, новые применяются к будущим заданиям (JOB-06); регулярные задания создаются вручную из шаблона (расписание запуска — с VS-5); методичка — инструкция в задании с версией на момент выполнения (JOB-03).
- [ ] Бот исполнителя и эмуляция через общий ScenarioRegistry: список заданий, принять/отказаться («Не могу выполнить» с причиной), отчёт (текст + файлы через upload-url VS-3), визиты; «Нет доступа» с попытками связаться (WRK-04); сообщение о найденной проблеме (JOB-04).
- [ ] Кабинет: очередь заданий, назначение исполнителя, приёмка/замечания, возврат на доработку, шаблоны, общая работа и связывание обращений; административное закрытие с проверкой и основанием (WRK-07/15), закрытие отмечается отдельно от подтверждения жителем.
- [ ] Гейт ADR-006: передача результата работы разблокируется проверками заданий; `work_execution_required` не сбрасывается сменой вида после начала работ; приёмка задания ≠ подтверждение обращения.
- [ ] Тесты: модульные (FSM-переходы, агрегированные состояния общей работы, версии отчётов и шаблонов, чек-листы), интеграционные (RLS, транзакции, идемпотентность повторов, append-only `task_log`); проверка интерфейса, документация; PR в main создаётся после фиксации результата, без merge.

## Границы срезов (за рамками VS-4)

- Таймеры и напоминания заданий — VS-5 (LLD-05 §VS-5, согласовано 17.10.2026): эскалация зам → председатель при отсутствии реакции (WRK-01), напоминание по сроку непринятия (WRK-02), напоминание 48 ч и проверка через 7 дней (WRK-07), напоминание в дату отложки (WRK-09), первый ответ 2 рабочих часа (TIM-05). В VS-4 `due_at` и даты фиксируются, напоминаний нет.
- Строки 15.2 с TIM («Неответивший автор — WRK-07, TIM-01», «Задержка/перенос — WRK-09, TIM-04–06») принимаются после VS-5; нельзя выдавать их отсутствие за выполненную приёмку.
- Расписание запуска регулярных заданий (pg_cron, LLD-04 §2) — VS-5 (согласовано 17.10.2026): в VS-4 задания из шаблонов создаются вручную; строка 15.2 «Регулярная работа — JOB-02–06» в части пропуска по расписанию (JOB-05) принимается после VS-5, но версии и чек-листы (JOB-02–03, JOB-06) проверяются уже в VS-4.
- Условия старта платной услуги (`start_conditions`, PAY-08) — поле закладывается, проверка наполняется в VS-6.
- Документы-акты WRK-17–18 и отчётность REP — VS-8; в VS-4 достаточно отчёта и подтверждения по WRK-06–07, если акт не требуется регламентом.
- Аварийный срочный маршрут (JOB-04, EMG) — VS-7; в VS-4 найденная проблема создаёт задание/обращение обычным порядком.
