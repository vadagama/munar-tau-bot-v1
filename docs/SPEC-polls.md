# Спецификация VS-8: `polls`

Дата: 23.10.2026. Статус: согласовано пользователем 23.10.2026 сообщением «Делай», включая
предложения раздела «Решения для согласования».
Модуль [карты](VS8-CAPABILITY-MAP.md).
Стек, команды, структура, стиль, проверки и границы — [общая часть](SPEC-vs8-conventions.md).

## Цель и сценарии

POL-01–04: информационные опросы по дому/домам/ОСИ с одним актуальным ответом
на человека и сводными результатами. Опрос явно не является юридически
значимым решением собрания. Источники: требования §10, LLD-02 §8, LLD-03 §3.9.

Администратор создаёт черновик: вопрос, варианты со стабильными ключами,
аудитория, окончание. До открытия можно редактировать. После `draft → open`
вопрос, варианты, аудитория и срок неизменяемы. Продление и досрочное подведение
итогов запрещены. Исправление — отмена с причиной и новый опрос без переноса ответов.

Подтверждённый житель аудитории отвечает и меняет свой ответ до окончания.
Несколько квартир/ролей не создают дополнительных голосов. Проверяется
действующая связь внутри аудитории, а не любая связь с ОСИ.

Потеря последней подходящей связи в открытом опросе исключает ответ;
восстановление связи не восстанавливает его автоматически. Житель может
ответить заново до срока. Другая действующая связь внутри аудитории сохраняет
участие. Исключение и повторное участие сохраняются в истории без содержания
выбора в административном аудите.

## Завершение и гонки

Граница времени — серверное `now < closes_at`; задержка jobs не продлевает
приём ответов. По сроку формируется окончательный снимок количества участников
и распределения. Проверка потери права до границы применяется и при
запаздывании фонового закрытия; изменение связей после границы не меняет итог.

Это требует истории интервалов действительности связей либо транзакционно
сохранённого состояния участия на границе. Предлагается использовать события
связей и фиксировать право в транзакции каждого изменения; фон закрытия
восстанавливает состояние на `closes_at`, а не использует только текущие связи.
Конкретный SQL-механизм выбирается в техническом плане после проверки
существующей истории. Его отсутствие блокирует готовность POL-03.

Открытый опрос можно отменить с обязательной причиной; после срока отмена
не должна подменять состоявшееся завершение. Отмена не принимает ответы,
не показывает даже сводное распределение; участники уведомляются с причиной.
Транзакции голосования, отмены, отзыва связи и закрытия не допускают
двойного эффекта или подсчёта исключённого ответа.

## Приватность и права

Администратор видит число участников и распределение, без списка людей и
индивидуальных ответов. Житель видит свой ответ, участник — сводку после
завершения. История сохранённых голосов не выдаётся в DTO, журнал,
уведомление управляющему или экспорт. Техническая обратимость для владельца
инфраструктуры не маскируется обещанием необратимой анонимности.

Предлагается итоговую сводку завершённого опроса оставлять доступной
участникам окончательного снимка после переезда; отменённые результаты
никому через прикладной API не выдаются. Состав участников остаётся закрытым.

## Контракты и интерфейс

LLD-03: `POST /v1/polls`, `PATCH /v1/polls/{id}` только для черновика,
`POST/PATCH /v1/polls/{id}/answer`, `GET /v1/polls/{id}/results`.
Предлагаемые дополнения: список/карточка и
`POST /v1/polls/{id}/transitions` с `open` либо `cancel` и причиной.
Закрытие по сроку выполняет jobs, произвольного ручного `close` нет.
Изменение ответа передаёт ключ варианта и версию личного ответа;
чужие `person_id`, время и право участия из тела не принимаются.

Кабинет: список, форма черновика, публикация, отмена, агрегаты.
Бот жителя: доступные опросы, вопрос с отметкой информационного характера,
варианты кнопками, изменение ответа, итог. Бот сотрудника получает уведомления
по своей роли; управление опросами выполняется в кабинете.
Эмуляция использует реальные проверки связей тестовой персоны.

## Приёмка и проверки

- Один человек с несколькими связями/ролями имеет один актуальный ответ;
  изменение варианта не увеличивает число участников.
- Отзыв связи исключает голос только при потере всей аудитории;
  восстановление требует нового ответа; журнал не раскрывает вариант.
- Проверены переходы связей до/после срока при задержанном jobs;
  итог после завершения не пересчитывается из текущего реестра.
- После открытия нельзя менять исходные параметры ни API, ни ботом;
  точно на границе срока ответ отклоняется.
- Отмена с причиной уведомляет участников один раз; сводка отменённого
  опроса недоступна управляющему и жителю; ответы не переносятся.
- По API, экспорту, аудиту и ошибкам нельзя получить чужие индивидуальные ответы.

Vitest с управляемым временем проверяет границы и выборку;
PostgreSQL — уникальность, гонки и историю связей; браузер/симулятор —
путь голосования, изменения, исключения и отмены.

## Решения для согласования

Доступ участника окончательного снимка к итогам после переезда;
серверная временная граница и восстановление прав именно на момент окончания.
Остальные правила непосредственно следуют POL-01–04.
