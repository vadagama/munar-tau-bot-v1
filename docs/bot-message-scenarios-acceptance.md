# Приёмка каталога целых сообщений

18.10.2026, ветка `feature/bot-message-scenarios`. Спецификация —
[целые сообщения](specs/bot-message-scenarios.md), решение — ADR-011.

## Результат

250 доступных для редактирования полных сообщений; 110 старых ключей скрыты
из основного списка, но сохранены для истории и совместимости. Перенесены
регистрация, обращения, задания, аварии/публикации, справка, ошибки, 61 доменное
уведомление и варианты дайджеста. Формулировки «Помещения» сохранены.

В кабинете доступны сценарии/команды, цельный текст ru/kk, подписи кнопок,
примеры данных, предпросмотр Telegram и история текста вместе с кнопками.
Для `/newrequest` предпросмотр показывает всё сообщение, список помещений,
подсказки и кнопки; есть примеры без помещений, с одним и несколькими.

## Проверено

- Модульные тесты core/admin: рендер и escaping, варианты сценариев, соответствие
  runtime/preview, HTML, кнопки, наследование старых настроек, версии/сброс/откат,
  доставка дайджеста и разделение длинных сообщений.
- `npm run lint`, `npm run typecheck`, `npm test`: 496 core + 49 admin.
- `deno task check`, `deno task lint`, `deno task test`: 50 тестов.
- Сборка кабинета и проверка на секреты успешны. Сохраняется предупреждение Vite
  о размере общего JS-chunk, не связанное с корректностью редактора.
- Миграция `20261018090000_message_buttons.sql` дважды применена только к Sydney
  под session advisory lock `(814733,3)`. Проверены ограничения JSON/RLS/гранты.
- Локальный кабинет проверен в браузере с настоящим сервисом и SQL-репозиторием:
  открытие полного сообщения, выбор примера/языка, изменение текста и кнопки,
  сохранение, история, сброс и откат. Повторное чтение store подтвердило совпадение
  runtime с сохранённой версией. SQL-проверка также подтвердила исторические
  подписи меню после переименования/сброса и запрет присвоения их другой команде. Тестовые версии/аудит полностью откатились
  внешней транзакцией; фиктивные данные не остались в БД.
- Независимая проверка выявила и помогла исправить потерю даты/настроек при
  пересборке дайджеста, JSON null при сбросе кнопок, неоднозначное наследование
  фрагментов и устаревающие подписи reply-клавиатур.
- Read-only инвентаризация Frankfurt: активных пользовательских переопределений
  нет, сообщений с неоднозначным переносом нет. Перенос проверен тестами.

## Границы проверки и выпуск

Полный очищающий интеграционный прогон не запускался. Реальная отправка жителям
не выполнялась; браузерная проверка использовала локальную тестовую авторизацию.
Функции и кабинет на демонстрационном стенде не обновлялись этой задачей.

После согласования PR: сначала применить миграцию кнопок, затем развернуть
api/bot-webhook/jobs и кабинет. Проверить `/newrequest`, меню обоих ботов и
уведомления на тестовых персонах, сохранение/откат в кабинете. Существующие
материализованные уведомления сохраняют прежний текст; настройки применяются
при новом рендере. Старые версии и payload остаются совместимыми.
