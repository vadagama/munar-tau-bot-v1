# Спецификация: приглашение и привязка жильца собственником

Дата: 24.10.2026. Статус: согласовано пользователем 24.10.2026 («Да, нормальный сценарий. Можно делать»).
Основания: REG-03/REG-13, ADR-015 (анкета-минимум), ADR-020 (разделение приглашения и привязки).

## Цель

Разделить «приглашение жильца» и «выдачу доступа»: по ссылке-приглашению жилец
только регистрируется в системе, а собственник затем сам привязывает его к
одному из своих помещений и выбирает роль. Это убирает фиксацию помещения и
роли до отправки ссылки, упрощает шаг приглашения до одного нажатия и даёт
собственнику контроль на этапе привязки.

## Три функции собственника

1. **Пригласить (`/invite`)** — одно нажатие: бот создаёт приглашение и
   присылает Deep Link `/start invite_<токен>` со сроком действия 72 ч
   (TIM-регламент `invite_expiry`). Помещение и роль на этом этапе не
   выбираются. Собственник пересылает ссылку жильцу любым способом.
2. **Привязать (`/bind`)** — собственник выбирает жильца из списка
   «зарегистрировались по моим приглашениям, ещё не привязаны к моим
   помещениям», затем помещение (кнопками) и роль (арендатор / проживающий /
   другое; собственность не выдаётся). Привязка создаётся сразу активной
   (основание: аренда для арендатора, семья для остальных), жилец получает
   уведомление. Из уведомления «жилец зарегистрировался» собственник попадает
   в привязку кнопкой с готовой ссылкой на человека.
3. **Доступы (`/accesses`)** — один экран с двумя секциями:
   «Выданные доступы» (привязки, отзыв с обязательной причиной, спор) и
   «Отправленные приглашения» (неиспользованные ссылки, отзыв без причины).

## Регистрация по приглашению

- Новый пользователь: мастер язык → имя → телефон → согласие (как при
  `/register`), после согласия создаётся персона, профиль и **одобренная
  анкета без помещения** (REG-01-модель). Ссылка помечается использованной.
- Уже зарегистрированный пользователь по ссылке: ссылка помечается
  использованной, инициатор получает уведомление «уже зарегистрирован,
  можно привязать» — подтверждение личности ссылкой без нового мастера.
- Инициатор в обоих случаях получает уведомление с именем жильца и кнопкой
  «Привязать» (`/bind <id>`); в эмуляции — в симулятор, наружу — только
  реальным профилям.

## Границы

- Привязать можно только человека, зарегистрировавшегося по приглашению
  этого собственника (`invite.created_by` + `status='used'`); себя — нельзя.
- Роль `owner` не выдаётся ни приглашением, ни привязкой.
- Жилец с действующей связью с помещением не привязывается повторно к нему;
  к другому помещению того же собственника — можно.
- Активные приглашения старого типа (с помещением) при миграции гасятся
  (`status='expired'`); обратной совместимости сценария нет — старая ссылка
  отвечает «приглашение недействительно».
- Администраторов о привязках бот не уведомляет — фиксирует аудит
  (`connection.bind`); рассмотрение анкет-привязок через `/pending` не
  возвращается.
- Кабинет продолжает читать список приглашений через API; новые приглашения
  отображаются без помещения.

## Приёмка

- `/invite` создаёт приглашение одним нажатием, у не-собственника — отказ.
- `/bind`: пустой список → подсказка с кнопкой «Пригласить»; полный проход
  человек → помещение → роль создаёт активную связь и аудит `connection.bind`.
- `/accesses`: обе секции на одном экране; отзыв приглашения не требует причины.
- Ссылка `/start invite_*`: новый пользователь регистрируется без помещения,
  существующий — consume без мастера; инициатор уведомляется с кнопкой.
- Все новые реплики и кнопки — в каталоге шаблонов, ru+kk; команды в тексте
  ответов не дублируются.
