# Выбор дома и контекстные кнопки (REG-11, REG-02a, UI-01)

Первый вопрос о доме в `/add` показывает только «Отменить». При неверном или пустом вводе пользователь получает все дома из актуального каталога: группы «Очередь 1» … «Очередь 5», затем «Очередь не указана». Внутри группы номера отсортированы естественно и перечислены через запятую. Номера — Telegram-ссылки выбора, тело и подписи берутся из каталога ru/kk. Пустой каталог имеет отдельное сообщение. Номер по-прежнему можно ввести текстом; варианты с дефисом, слешем и пробелом сохраняются.

Ссылка `house_UUID_token` содержит одноразовый для шага маркер (12 hex-символов). Она проверяется до переключения сценария, затем после привязки канала к профилю/сеансу. Выбор перечитывает каталог и проходит обычный шаг формы; после выбора маркер удаляется. Старые, повреждённые и чужие ссылки не восстанавливают форму и не меняют текущий диалог. Симулятор перехватывает ссылки своего бота и отправляет точный `/start` payload; Telegram использует тот же сценарий. Длинные списки доставляются существующим механизмом разбиения уведомлений.

Общий navigationReply больше не добавляет несвязанные профиль/регистрацию/справку к ответам ввода регистраций, обращений, заданий, аварий и настроек: если у ответа нет контекстных действий, добавляется только отмена. Явные кнопки сценария сохраняются, отмена не дублируется. Главное меню остаётся на явном старте/отмене.

Проверки: `building-hints.test.ts` — очереди, порядок номеров, экранирование, ru/kk, пустой каталог, маркер шага и паритет превью; `registration.test.ts` — начальный вопрос, ошибка, выбор и повтор старой ссылки; `inbound.test.ts` — доставка через Telegram и сохранение чужого диалога; `navigation.test.ts` — пять сценариев без общего меню; `registration-simulator.test.tsx` — выбор ссылкой в симуляторе. В браузере на тестовом стенде проверены начальный вопрос, группы и переход по номеру к типу помещения. Реальные сообщения пользователям не отправлялись.
