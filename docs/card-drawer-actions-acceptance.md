# Приёмка действий в шторках (ADR-012)

## Общие критерии

1. Открыть карточку из таблицы и доски. В DOM виден один `dialog`.
2. Открыть короткое действие: форма находится в этой шторке, сведения объекта
   остаются видимыми, другое бизнес-действие нельзя начать до завершения текущего.
3. Открыть длинную форму: в той же шторке видны заголовок объекта и форма.
   Отмена возвращает карточку, фокус на вызвавшее действие и прокрутку.
4. Изменить поле и нажать отмену/Esc/крестик. Ввод сохраняется до явного выбора
   «Выйти без сохранения»; «Продолжить редактирование» возвращает к форме.
5. Во время отправки/загрузки проверить крестик, Esc, маску, отмену, повторную
   отправку и ранее показанную кнопку отказа от изменений: операция не прерывается.
6. Ошибка API находится в текущей панели; поля сохраняются. При 409 обновляется
   версия, автоматической повторной отправки нет.
7. Проверить ширины 320, 768, 1024, 1440 px, Tab и возврат фокуса.
8. Отмена не выполняет доменный POST/PATCH/DELETE. Права и обязательные поля
   соответствуют прежнему сценарию и серверному PDP.

## Матрица

| Экран | Короткие формы | Полный режим |
| --- | --- | --- |
| Обращения | Все переходы FSM, ограничение сообщения, визиты | Создание, исправление места |
| Задания | Переходы FSM, приёмка/доработка, визиты, связывание найденной проблемы | Создание, отчёт/найденная проблема, отмена/замена, смена методички |
| Инциденты | — | Создание, смена дежурства, назначение сигнала, переходы, обновление охвата, связи, передача итога |
| Публикации | Медиа, согласование, публикация, расписание, архив, план/восстановление, сообщение о проблеме | Создание и редактирование |
| Реестр | — | Создание/редактирование здания, помещения, лица, связи; восстановление Telegram |
| Общие работы | Связь/отсоединение обращения, завершение | Создание и отмена |
| Шаблоны заданий | — | Создание/версия, ручной запуск, расписание |

Настройки обращений открываются самостоятельной шторкой уровня страницы.

## Автоматизация

Из `source/`: `npm run lint`, `npm run typecheck`, `npm test`,
`npm run build -w admin`, `sh tools/scripts/check-build-secrets.sh admin/dist`.

Регрессии: `action-panel.test.tsx`, `card-drawer.test.tsx`, `requests.test.tsx`,
`tasks.test.tsx`, `incidents.test.tsx`, `registry.test.tsx`, `job-templates.test.tsx`.
Они проверяют единственную поверхность, возврат, busy/dirty, сохранение требований
приёмки отчёта, гонки загрузки и повторное подтверждение после 409.

Браузерная проверка проводится в локальном Chromium с изолированными вымышленными
ответами API: пять основных страниц, короткая/длинная форма, отмена с вводом,
вложенный визит и ширины 320/768/1024/1440. Это проверка UI, не сквозная приёмка
авторизации, PostgreSQL или Telegram. Интеграционные тесты без отдельного запроса
не запускаются.

  потерю фокуса, обход busy через отказ от изменений и сохранение старой карточки
  при отзыве доступа во время обновления.
- Mutation check: инверсия busy guard вызывает падение регрессии; исходник
  восстановлен побайтно.
- Существующее предупреждение Vite о чанке больше 500 kB сохраняется.
