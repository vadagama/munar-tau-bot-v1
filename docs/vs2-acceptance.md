# VS-2 — проверка реестра и регистрации

Основание: REG-01–14, IMP-01–13, требования §15.2 и модель процессов §8. Текущий прогон и состояние задач — [план VS-2](../tasks/plan-vs-2.md).

## Бот

1. `/register`: ru/kk → ФИО → телефон → здание → тип (1–4 либо код) → номер → отношение (1–4 либо код) → явное согласие. До подтверждения данные помещения/жильцов недоступны.
2. `/status` показывает решения. `/edit ID` исправляет неподтверждённую/отклонённую анкету с сохранением её ID. `/add` независимо проверяет ещё один объект.
3. Подтверждённый собственник: `/objects` → `/invite ID_ПОМЕЩЕНИЯ tenant|resident|other`. Приглашение одноразовое; команда `/start invite_ТОКЕН` запускает проверку данных и согласия. Собственность приглашение не выдаёт.
4. `/pending` показывает собственнику анкеты арендаторов; `/approve ID` либо `/reject ID причина`. После 48 календарных часов без решения ожидание передаётся сотруднику, доступа ещё нет.
5. `/accesses` показывает выданные доступы, ID связи для `/revoke ID причина` и ID регистрации для `/dispute ID причина`. Можно отозвать только свой выданный/подтверждённый доступ, чужой — оспорить. Возражение само по себе не отзывает доступ.
6. Смена собственника: администратор прекращает только соответствующую связь в кабинете, с причиной. Доступы/приглашения этого собственника к тому же объекту прекращаются; другие собственники и объекты сохраняются.

## Импорт

Четыре листа из шаблона, постоянные UUID при выгрузке; первичный импорт — физлица-собственники. Импорт телефона нормализуется до проверки уникальности. Точный ключ помещения: здание + тип + номер, без подъезда и этажа. Данные существующих записей не перезаписываются. Любая ошибка запрещает весь commit. Успешный импорт создаёт pending-связи без Telegram-профилей. Дата импорта — created_at связи, а не start_date собственности.

## Сроки, права, аудит

- 72/48 часов включают ночь/выходные. Рабочие 12/36 часов считают ежедневный график 08:00–20:00 Алматы. Новая версия не переносит старый срок.
- При отсутствии администратора выбирается действующий заместитель, затем председатель. При отсутствии реакции jobs передаёт этап с отдельным локальным интервалом; общий срок спора остаётся прежним. Просрочка не закрывает спор и не выдаёт доступ.
- Чужой дом, экспорт без права и привилегированная операция в эмуляции — отказ. Тестовые анкеты/люди/помещения не смешиваются с настоящими; канал simulator не отправляет Telegram.
- Восстановление использует подтверждённый Telegram новой анкеты, ручную проверку личности и журнал; телефон/metadata не являются доказательством. Старый профиль и сеансы закрываются. Новый кабинет связывается по auth.identities провайдера custom:telegram.

## Среда и проверки

Модульные тесты Node/Deno, интеграционные против TEST_DATABASE_URL (с очищением только вымышленной dev-БД), линтеры/тайпчек, сборка и scan секретов. Браузерная проверка Chrome — отдельный стенд страниц с синтетическими API-данными; это не проверка работающего OIDC/Telegram. До проверки настоящего входа настройте [провайдер и BotFather](setup-telegram-oidc.md). Jobs использует существующие X_JOBS_SECRET, TELEGRAM_BOT_TOKEN и SUPABASE_DB_URL; вызов по расписанию обязателен для сроков/доставки.
