# Каталог жителей (REG-02a, UI-01)

На `/users/residents` сохранён список жителей без действующих служебных назначений. Добавлены адрес (название и обозначение здания действующей привязки), статус основной анкеты и перечень действующих привязанных помещений с типом, номером и отношением жителя. Несколько зданий показаны вместе; без привязок — «Адрес не указан» и «Помещения не привязаны», без анкеты — «Нет анкеты».

`GET /v1/registry/persons` дополнен полями `registration_state`, `registered_at` и `linked_premises` (id помещения, building_id/building_code/building_name, kind, number, role). Выборка анкеты исключает superseded_by, предпочитает основную запись без помещения; для старых данных без основной анкеты берёт актуальную запись привязки перед отозванными. `registered_at` — дата создания выбранной анкеты. Исправления на проверке показывают фактический статус основной записи. Действующие помещения ограничиваются областью registry.read и признаком is_test; прежние права на список людей сохранены.

По образцу обращений фильтры применяются автоматически: поиск по ФИО/телефону/Telegram/адресу/помещению, статус регистрации (включая отсутствие анкеты), здание, наличие помещений, период регистрации с/по включительно по времени Алматы. Фильтры сочетаются, строки других разделов реестра не меняются. Если у записи нет даты анкеты, при фильтрации по периоду она не отображается. Данные получаются одним запросом каталога без запросов на каждого человека.

Имя в Telegram (23.10.2026): `GET /v1/registry/persons`, `/v1/registry/staff`, `/v1/registrations` и `/v1/registrations/invites` отдают имя аккаунта (`telegram_username`, для приглашений — `created_by_telegram` пригласившего) и во всех четырёх таблицах есть колонка «Telegram» с поиском по нему. Имя — display-only метаданные, не ключ аутентификации и сопоставления (ADR-001/004): сопоставление записей ведётся по `telegram_user_id`, имя не объединяет карточки. Хранится в `profile.telegram_username` (текущее имя действующего профиля) и снимком в `registration.telegram_username` (у ожидающих анкет профиля ещё нет); актуализируется при входящих обновлениях обоих ботов (best-effort, сбой не ломает обработку), при одобрении анкеты профиль получает имя из снимка.

Проверки: `registry.test.tsx` — колонки, поиск, сочетание фильтров и граница даты Алматы; `tools/scripts/check-resident-directory.ts` — настоящий SQL на синтетических CTE в read-only транзакции (основная анкета, исторические дубли, отозванные связи, область и разделение тестовых данных). Скрипт не меняет таблицы и не выводит персональные данные.
