## 1. Резюме (Executive Summary)

Решение архитектурно зрелое и дисциплинированное для своего масштаба и стадии (прототип на облачном стенде, срезы VS-0…VS-8). «Вертикаль» — образцовая: единый конвейер API (`CORS → JWT ES256 → профиль → сеанс → Actor → PDP → обработчик → аудит`), deny-by-default PDP, RLS как второй рубеж с включением в каждой миграции, outbox-паттерн и транзакционная дедупликация webhook, append-only журналы. Документация (`AGENTS.md`, HLD, LLD, ADR) поддерживается на уровне, редком для проектов такого размера, и реально соответствует коду.

Главные системные риски лежат в «горизонтали»: декларируемый порт-паттерн («порты, SQL-репозитории») фактически реализован для 3 из 16 доменов, остальной SQL исполняется прямо в сервисах (~760 вызовов в 97 файлах); слои `bot` ↔ `domains` связаны двунаправленно (36 файлов доменов импортируют presentation-слой). На этом фоне решение отключить интеграционные тесты в CI (23.10.2026, из-за затрат) смещает поведенческие проверки SQL-путей на статический schema-drift-тест и хрупкие текстовые заглушки — регрессии SQL-поведения уже доходили до прода (инцидент 2026-10-23).

Точечных критических проблем (P0) не обнаружено. Из прикладного: у кабинета нет CSP/security-заголовков при единственном `dangerouslySetInnerHTML` (предпросмотр шаблонов) — закрывается одним `_headers`. Итоговый health score ≈ **7.3/10**: промышленная дисциплина в безопасности, документации и CI при стадийной зрелости кода (частичная гексагональность, god-сервисы 1205/1068 строк).

## 8. Архитектурные риски (структурные, не точечные)

1. **Раскол «декларация ↔ факт» гексагональности.** Образец для копирования в документации — порты и фейки; реальный образец большинства доменов — SQL в сервисе + SQL-заглушки. Каждый новый домен, реализованный по второму образцу, увеличивает стоимость миграции на порты (D-002, D-012).
2. **Горизонтальная связность держится на конвенции, а не на границах.** Междоменные импорты и парные циклы (`tasks`↔`requests` — `tasks/service.ts:17-19` ↔ `requests/service.ts:6-7`; `notifications`↔`polls`; `notifications`↔`initiatives`), «шина» `RegistryDeps` внутри домена registry. Изменение общего контракта — каскад без единой точки контроля (D-003, D-006).
3. **Смещение тестовой стратегии.** 1516 быстрых unit-тестов при выключенных интеграционных проверках SQL-поведения: риск класса «тихих» регрессий (уже реализовался инцидентом 2026-10-23). Schema-drift-тест закрывает ссылки на колонки, но не поведение (D-004).
4. **Миграция в self-hosted (Казахстан, ADR-003).** Незакрытые до неё пункты: клиентский хардкод `+05:00` (D-007/Q-002), повторная проверка REVOKE/RLS на self-hosted (предупреждение в `source/db/rls.sql:20-23`), отсутствие CSP кабинета (D-001).
5. **Связка ядра с Telegram-слоем** как барьер для выделения `core` в пакет и переиспользования сценариев вне Telegram (D-003); при росте сценарного слоя — предпосылки циклов инициализации.
