# VS-5 — регламенты и уведомления: состояние реализации

Дата: 17.10.2026. Ветка `feature/vs-5-regulations-notifications`, изолированная от разработки VS-4.

## Реализованный независимый контур

- TIM-03/04/05: единый `work_schedule`, новые версии рабочих правил при смене графика, автор/причина и аудит. Уже запущенные сроки сохраняют версии и даты. Исторические версии защищены от UPDATE/DELETE.
- TIM-07: правовое основание, редакция, дата действия, область и границы хранятся явно. При создании версии основание копируется в `legal_basis`; обычный API не изменяет правовое основание. Незаданные или нарушенные границы дают `RULE_LEGAL_BOUNDARY`.
- TIM-05: первый ответ по рабочему графику; ближайшее открытие сохраняется при регистрации и показывается ботом. Содержательный ответ отменяет таймер. Просрочка не обнуляется.
- WRK-07: напоминание автору через 48 календарных часов и проверка администратором через 7 дней. Таймеры привязаны к версии результата. Подтверждение, отзыв и доработка погашают устаревшие таймеры; автоматического закрытия нет.
- NTF-01/03: предпочтения publication/work.report (сразу, сводка, выключено), request.status (сразу, выключено), ru/kk. Обязательные сообщения не отключаются. Сводка следует окончанию смены, повторно проверяет аудиторию и не отправляет пустое сообщение. Большая сводка продолжается порциями с сохранением отсечки состава.
- NTF-02: outbox с уникальным ключом, материализация notification, lease отправки и защита от устаревшего воркера, повтор по retry_after, пять попыток, немедленная окончательная ошибка при блокировке бота. Текст транспортного исключения не сохраняется. Окончательная ошибка важного уведомления создаёт единственную задачу контакта; результат сотрудник фиксирует явно. Для обращений уведомляются действующие обработчики.
- Перед отправкой повторно проверяются профиль, полномочия/доступ к обращению и связи с домами. Служебные и жительские аудитории разделены; simulator никогда не вызывает Telegram.
- Кабинет: версии регламентов, предпочтения и ошибки доставки в области сотрудника, запись результата связи. Причина окончательной ошибки и состояние контакта также показываются обработчику в карточке обращения. Бот/эмуляция: общий сценарий `notifications` и команда `/notifications`.

## Проверка пользователем после развёртывания

1. Председателем изменить время закрытия смены. Создать новое обращение; сравнить его срок с обращением, созданным до изменения. Старый срок и версия не меняются.
2. Обычным администратором без права управления регламентами попытаться сохранить настройку: сервер возвращает 403. В эмуляции изменение регламентов запрещено.
3. Передать результат вопроса/жалобы, дождаться тестового срока напоминания. Обращение остаётся открытым. Вернуть результат на доработку; предыдущие напоминания больше не срабатывают.
4. В тестовой эмуляции открыть сценарий «Уведомления», отправить `/notifications`, затем `/notifications новости сводка ru`. Обязательные события недоступны для отключения.
5. Для окончательной ошибки важной доставки открыть «Уведомления → Ошибки доставки», записать фактический результат попытки связи. Это не меняет состояние обращения и не подтверждает согласие жителя.

## Автоматические и интерфейсные проверки

- Модульные: 219 тестов ядра и 25 кабинета прошли; включены TIM-03/04/07, календарь и NTF-01/02/03.
- Интеграционные: `source/core/tests/integration/notifications.test.ts`, только Sydney, общий session advisory lock `(814733,3)`. Первые два сценария прошли. Расширенный прогон завершился ошибкой соединения Supabase `EAUTHTIMEOUT` до применения миграций и запуска тестов; повтор ожидает общую блокировку. Ожидание не считается успешной проверкой.
- Deno: check/lint/test (39 тестов) прошли после заключительного ревью.
- Кабинет: typecheck, lint, unit, build и secret-scan прошли после заключительного ревью. Сборка сохраняет существующее предупреждение Vite о крупном JS-бандле.
- Браузер: локальный стенд с вымышленными данными и mock API, форма результата связи, история версий и редактор графика проверены; ошибок консоли нет. Это не сквозная проверка развёрнутого API/OIDC. Временные файлы стенда удалены.

## Не считать полной приёмкой VS-5

Пункт 5 утверждённого `tasks/plan-vs-5.md` зависит от стабильных контрактов VS-4: непринятие задания, эскалации, резервный ответственный при ошибке назначения, запуск регулярных заданий и сохранение пропусков JOB-05. В `main` VS-4 ещё отсутствует; эти сценарии не подключены и не приняты. Значения ненастроенных сроков не подменяются вымышленными нормативами.

Публикации VS-7 и опубликованные отчёты последующих срезов должны вызывать общий enqueueNotice с разрешённой аудиторией; пока дайджест проверяется интеграционными событиями. Финансовая аудитория PAY-08 подключается с VS-6. Аварийное дежурство/резерв — VS-7.
