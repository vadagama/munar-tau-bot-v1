# SPEC: registration-lite — анкета-минимум и обращения без привязки помещения

Модули `registrations` и `requests` ядра. Заменяет спеку `SPEC-registration-binding.md` (дизайн «непривязанная анкета с текстом помещения» не реализован — вместо него принят анкета-минимум). Основание: решение владельца 19.10.2026, ADR-015. Статус: реализовано в ветке `feature/registration-lite`.

## Цель

Убрать барьер входа: житель регистрируется без дома, помещения и роли и сразу получает доступ к обращениям; помещение привязывается в любой момент отдельной анкетой через `/add`. Обращение по адресу вводится одной строкой без распознавания дома.

## Что меняется

### Схема (`source/db/migrations/20261019150000_registration_lite.sql`)

- `registration.premises_id` и `role` → nullable (`drop not null`). Существующие строки не трогаются; связи и приглашения без изменений.

### Домен (`source/core/src/domains/registrations/`)

- `submitRegistration`: бот может подать анкету без `premises_id`/`role` (draft = `{language, full_name, phone_e164}`); заявка от сотрудника по-прежнему требует помещения. Этап — `initialStage(null)`; уведомления ревьюерам без домового сужения и без `registrationAccess`; аудит с пустым `scopeBuildings`.
- `reviewRegistration`: approve без помещения создаёт/обновляет person+profile (язык) без связи; привязка к карточке реестра (`person_id`) не требует связи с помещением; dispute без помещения — `INVALID_TRANSITION` (оспаривать нечего — связи нет).
- `listRegistrations`, `sweepRegistrations`, бот и кабинет — LEFT JOIN premises; эскалации и аудит корректны на NULL.

### PDP (`pdp/evaluate.ts`, `domains/requests/`)

- `active_author` для обращений с `premises_id IS NULL` — действующий профиль автора (profile без `archived_at`, person активен); для привязанных помещений — прежняя связь с помещением.
- Видимость сотрудников при `building_id IS NULL` — chairman/administrator/deputy с сохранением `chairmanOnly`; `listRequests` допускает `building_id IS NULL` в области администратора.
- `validateLocation`: адресное обращение создаёт автор с действующим профилем (без связей); привязанное помещение требует действующую связь.

### Бот (`source/core/src/bot/`)

- `/register`: язык → имя → телефон (пример `+7 777 777 16 76`) → согласие без помещения/роли (`message.registration.lite_consent`). Шаги building/kind/number/role остаются только в `/add` и `/edit` привязанной анкеты.
- `/add` без профиля — приглашение сначала `/register`; `/fix` анкеты без помещения не предзаполняет premises/role; guard `/register` и `/status` видят анкеты без помещения (LEFT JOIN, метка «помещение не указано»).
- `/newrequest`: без подтверждённых помещений шаг адресата пропускается → адрес одной строкой (`message.requests.address`), `place_label` = текст; у жителя с привязкой прежнее меню и старый синтаксис «дом КОД …»/«территория …».
- Файловый диалог после описания: «Добавите файл/фото?» [да/нет] → медиа → «Хотите добавить ещё?» [да/нет] → проверка → `/sendrequest`; сохранение файла асинхронное.
- Дом текстом с автопроверкой: `/add` и «Общее имущество → в доме» — «Напишите номер вашего дома (например, 107/2)»; нормализация «/», «-», пробелов и слова «дом/үй»; не найден — повтор с примером.

### Кабинет (`source/admin/src/pages/`)

- Анкета без помещения: «Помещение не указано», пустая роль — «—», подтверждение = предоставление доступа без привязки.
- Обращение без дома: место = текст адреса; адресные обращения видны администраторам в списке.

### Каталог шаблонов (ADR-010/011, ru+kk)

Новые ключи: `message.registration.lite_consent`, `registration.pomeschenie_ne_ukazano`, `message.requests.address`, `message.requests.attachments_prompt`, `message.requests.attachments_wait`, `message.requests.attachments_more`, notice `notices.registrations_service_submit_registration_lite`. Изменены: `registration.telefon_7` (пример телефона), `message.requests.verify` (без инструкции о файлах), шаблоны выбора дома — текстовые подсказки.

## Ограничения и открытые вопросы

- Адресные обращения не маршрутизируются по домам — общая очередь; пересмотр по нагрузке (ADR-015).
- Заместитель видит адресные обращения наравне с администратором — подтвердить при приёмке.
- Кабинетная привязка помещения (старые B3/B4) — вне объёма.
