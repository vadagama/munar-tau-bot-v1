# Приёмка шаблонов сообщений ботов

Дата: 18.10.2026. Основание: спецификация §14, ADR-010.
Ветка: `feature/bot-message-templates`.

## Реализовано

258 ключей каталога ru/kk: ошибки, регистрация, обращения, задания,
аварии, справка, уведомления и общие фрагменты. Оценка в плане была ниже:
включены условные переводы из requests.ts и варианты составных уведомлений.
Редактор `/templates`: поиск/секции, оба языка, вставка переменных,
предпросмотр, причина, история, откат новой версией и сброс.
API/PDP, аудит, проверка base_version и идемпотентность общие для кабинета.

## Проверено

- Unit: движок и HTML-валидация, golden по перенесённым файлам, уникальность
  ключей и валидность дефолтов, версия/конфликт/откат/сброс/идемпотентность,
  атомарность версии и аудита, права и эмуляция.
- Диспетчер на fake SQL: новый и старый payload, выбор языка, свежая версия
  следующего пакета. HTML-переопределения справки/ошибок/инцидентов.
- Кабинет: сохранение ru/kk с причиной/base_version, предпросмотр, сброс,
  откат, обязательная причина, read-only эмуляция, отсутствие доступа у
  чужой роли, вставка переменной в выбранное место казахского текста.
- Deno: регистрация защищённых API-маршрутов, обязательный ключ preview,
  запрещённый HTML и отказ чужой роли; остальные тесты функций.
- Миграция применена дважды только на Sydney через session pooler и simple
  protocol, с advisory lock `(814733,3)`. Проверены RLS и отозванные grants.
  UPDATE/DELETE версии отклонены append-only-триггером в откатываемой
  транзакции. Данные не очищались.
- Ручной браузерный цикл на локальной странице с настоящим TemplatesPage,
  сервисом и Sydney SQL: поиск errors.INTERNAL → HTML ru/kk → preview →
  сохранение v1 → сброс v2 → откат v1 как v3. История показывает автора,
  причину и все версии. Рендер botErrorText сразу меняется; после сброса
  возвращается дефолт, после отката — сохранённый HTML. Три записи аудита.
  Временный harness обходил JWT только локально с фиксированным актором;
  конвейер аутентификации проверяется отдельными Deno-тестами.
  Все данные ручной приёмки отменены транзакцией, временный сервер удалён.

Итог автоматических проверок: 449 тестов ядра, 47 тестов кабинета,
50 тестов Deno — успешно. Lint/typecheck, сборка и secret-scan — успешно.
Grep-барьер: оставшиеся `pick()` в перенесённых файлах относятся только
к подписям кнопок, исключённым из объёма.

## Команды

Из `source/`: `npm run lint`, `npm run typecheck`, `npm test`,
`deno task check`, `deno task lint`, `deno task test`,
`npm run build -w admin`, `sh tools/scripts/check-build-secrets.sh admin/dist`.

Полные ручные сценарии регистрации/обращения/задания через эмуляцию
не повторялись; их регрессия проверена модульными сценариями и golden-снимками.

Полный интеграционный набор не запускался: нужен отдельный явный запрос
владельца. Проверки настоящих Telegram-отправок не выполнялись; тестовая
отправка не входит в согласованный объём. Frankfurt и Cloudflare не обновлялись.
Vite сохраняет предупреждение о размере общего JS-чанка кабинета.

## Проверка после разрешённого развёртывания

1. Применить миграцию до обновления функций; затем развернуть api,
   bot-webhook, jobs и кабинет в согласованной среде.
2. Войти ролью administrator/chairman/tech_admin, открыть «Шаблоны».
3. Изменить текст ошибки ru/kk, проверить preview и сохранить с причиной.
4. Получить соответствующую ошибку в эмуляции; проверить новый текст.
5. Откатить, затем сбросить; проверить историю и журнал действий.
6. Проверить отказ executor/resident и невозможность правки в эмуляции.
7. Уведомления в outbox до материализации используют последнюю версию;
   уже созданные notification сохраняют прежний текст.

Нельзя проверять миграцию или очищать данные на Frankfurt. Новые дефолты
меняются кодом с обновлением golden-снимков; редактор не добавляет новые ключи.
