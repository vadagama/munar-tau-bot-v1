# ADR-012: действия внутри единственной шторки карточки

Дата: 18.10.2026. Решение согласовано пользователем после аудита PR #36.

## Контекст

PR #36 перенёс карточки обращений, заданий, инцидентов, публикаций и редактирование
реестра в шторки. Формы действий сохранились в Modal, включая формы вложенных
визитов, найденных проблем и отчётов. Для выполнения действия возникали два
перекрывающих слоя; ошибки отправки часто оставались на странице под маской.

## Решение

Карточка и её подзадачи используют один `CardDrawer`.

- Короткое действие раскрывает `ActionPanel` в начале шторки; ниже остаются
  сведения карточки. Другие действия временно недоступны.
- Длинная форма использует полный режим `ActionPanel`: скрывает обычное содержимое
  карточки в той же шторке. Заголовок объекта сохраняется. Отмена возвращает
  сведения карточки, фокус и позицию прокрутки.
- `ActionPanel` переносит форму в область действий текущего `CardDrawer` через
  React portal. Это позволяет переиспользовать `TaskVisits` и `TaskProblems`
  из разных карточек, сохраняя единственный dialog и существующий API.
- Создание объекта использует ту же шторку; после сохранения открывается карточка.
  Восстановление Telegram — самостоятельная форма в шторке.
- Общие работы и шаблоны заданий размещаются на `/common-works` и `/job-templates`.
  Создание задания из этих разделов возвращает на `/tasks` с открытой карточкой
  или предвыбранной общей работой.
- Подтверждения ограничений сообщения и других чувствительных операций содержат
  последствия и конкретное действие; дополнительный Modal не открывается.

При отмене изменённой формы показывается предупреждение внутри панели:
«Продолжить редактирование» / «Выйти без сохранения». Esc и крестик следуют тому же
правилу. Во время отправки/загрузки закрытие и повторные действия блокируются.
При 409 обновляется версия карточки, введённые поля сохраняются; повторная
отправка возможна только после нового явного подтверждения.

Поля, обязательность причин, проверки отчётов, PDP и FSM REQ/WRK/EMG/PUB/REG
не меняются. Внутренние файлы не получают новую аудиторию.

## Альтернативы

- Вложенные шторки сохраняют несколько поверхностей и усложняют возврат.
- Перенос любой формы в поток карточки делает длинные отчёты и редакторы
  публикаций неудобными; для них выбран полный режим.
- Универсальный генератор доменных форм не нужен: общими остаются только
  представление, отмена, фокус и отображение ошибок.

## Проверка

[Сценарии приёмки](../card-drawer-actions-acceptance.md). Модульные проверки
используют вымышленные ответы API. Сквозные операции со стендом и интеграционные
тесты не входят в эту UI-задачу.
