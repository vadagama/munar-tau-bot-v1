# ADR-021: Главная кабинета — серверные очереди и аналитика

Дата: 25.10.2026. Статус: принято для реализации согласованного прототипа.
Основание: согласование главной в чате («Можно начинать делать»), REQ, WRK,
REG-01/02a, ROL/PRV и AUTH-06.

## Контекст

Прежняя главная считала первые страницы списков, не давала перехода к каждой
записи и повторяла просрочки отдельной плашкой. Счётчики не должны раскрывать
недоступные объекты, а список после нажатия на график должен соответствовать
его показателю и календарному интервалу.

## Решение

- `GET /v1/dashboard` возвращает разрешённые очереди с полным количеством и
  максимум 20 строками. Просрочки входят в «Требуют вашего действия».
- `GET /v1/dashboard/analytics?period=day|week|month|year` агрегирует обращения
  в PostgreSQL по времени Алматы: создано, закрыто и виды обращений.
- `POST /v1/dashboard/requests` применяет ту же область доступа до фильтров,
  подсчёта и пагинации. `measure=created|closed`, `from <= timestamp < to`,
  `kind`, `queue=new|attention`, поиск, статус и дом. Страница до 100 записей.
- Область управляющего обращениями общая с существующими staff queues:
  test-режим, дом, жалоба на самого сотрудника, направление председателю.
  Задания и аварии проходят объектный PDP до подсчёта. Архив заданий и аварий
  не загружается для главной. Для аварий scope/audience читаются одним SQL.
- Основная регистрация и привязка — разные очереди одних анкет; используется
  действующий сервис регистраций, включая его дедупликацию и область доступа.
- Ссылки содержат ID и ведут в существующий раздел. `entity_page=1` показывает
  рабочую карточку на странице с прежними формами и серверными проверками;
  обычное открытие из таблиц сохраняет существующую шторку.
- Порядок, видимость и 3/5/10/20 строк хранятся локально по profile/person/test.
  Это настройки представления, не полномочия. Неизвестные ID отбрасываются;
  сервер всегда определяет доступный состав. При смене персоны/ролей прежний
  ответ сразу скрывается, поздний ответ не переносится в новый контекст.
- Перенос поддерживает Pointer Events (мышь/касание); стрелки дают эквивалент
  для клавиатуры. Скрытые очереди не оставляют пустых мест.

## AI — продолжение в ADR-022

Согласованное место ассистента — над сеткой, на всю ширину. При отсутствии
доступа блок полностью исчезает, сетка поднимается. После выбора пользователем
DeepSeek и лимита подключение описано в [ADR-022](022-dashboard-deepseek.md).
Внешний запрос выполняется только после явного действия; контекст ограничен
полными количествами доступных очередей, без текстов и персональных данных.

## Альтернативы

Подсчёт загруженных списков в браузере отклонён: пагинация и PDP искажают
числа. Отдельная копия карточек отклонена: существующая карточка меняет
только поверхность показа. Смена React/AntD и новая библиотека DnD не нужны.

## Проверки

Модульные тесты календаря, SQL-предикатов, PDP, полных счётчиков, настроек,
URL-фильтра и карточки-страницы. Браузерный стенд изолированными fixtures
проверяет UI без обращения к рабочей БД. Интеграционные тесты и деплой
не выполняются без отдельного разрешения. Результат — `docs/home-dashboard-acceptance.md`.
