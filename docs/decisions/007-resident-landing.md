# ADR-007: отдельный статический лендинг жителей

Дата: 17.10.2026. Статус: принято в рамках задачи на лендинг.

## Контекст

Жителям нужна публичная стартовая страница с переходом в Telegram-бот ОСИ,
описанием обращений и регистрации (REG-01/02/04, REQ-03/06). По задаче пользователя
она публикуется отдельно от кабинета на Cloudflare Pages и оформляется отдельным PR.

## Решение

Добавить workspace `source/landing`: HTML/CSS и сборка Node, создающая QR-код
из той же ссылки, которая подставляется в кнопки. Результат `landing/dist` —
самостоятельный набор статических файлов для отдельного Pages-проекта.
Vite применяется только для локального просмотра; в браузере нет JavaScript.

Лендинг не зависит от кабинета, Supabase, авторизации и серверных секретов.
Фоновое изображение скопировано с текущей страницы входа: сборка лендинга
не зависит от незавершённых изменений кабинета. Данные и бизнес-правила
остаются в общем ядре; лендинг только объясняет вход в существующий процесс.

## Альтернативы

- Маршрут внутри SPA кабинета: связывает независимые публикации и загружает
  зависимости кабинета для информационной страницы.
- React и отдельный SPA: лишняя клиентская среда для текста и ссылок.

## Проверки

- Сборка и secret-scan включены в Node CI.
- Адаптивность, клавиатурный фокус, отсутствие ошибок в браузере.
- QR и кнопки ведут в один бот; нет форм и обращений к API.
- Публикация только в отдельный Pages-проект; инструкция в `source/landing/README.md`.

## Источники

- [Cloudflare Pages: Static HTML](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/).
- ADR-002 и ADR-003: кабинет и общие серверные правила остаются без изменений.
