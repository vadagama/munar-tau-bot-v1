# ADR-002: Статическая админка на Cloudflare Pages

Статус: принято пользователем. Развёртывание выполнено 2026-10-16: Pages-проект `osi-admin`, адрес `https://osi-admin.pages.dev`.

Дата: 2026-10-16.

## Контекст

Администраторам и председателю нужен веб-кабинет с реестрами, очередями, отчётами и настройками, доступный также с телефона. Статический интерфейс можно размещать отдельно от серверной логики и данных ОСИ.

## Решение

- Интерфейс: React + Refine Core + Ant Design; сборка через Vite.
- Результат сборки — статические HTML, CSS, JavaScript и ресурсы интерфейса; размещение на бесплатном тарифе Cloudflare Pages.
- Исходный адрес — `<имя-проекта>.pages.dev`. Развёрнут проект `osi-admin`: `https://osi-admin.pages.dev` (2026-10-16).
- Браузер исполняет интерфейс и обращается по HTTPS к Supabase Auth и общему серверному API. Вход описан в [ADR-001](001-telegram-auth.md).
- Cloudflare Pages обслуживает статические файлы. Pages Functions, SSR и проксирование бизнес-API через Cloudflare не требуются для принятой схемы.

| Где | Что работает |
| --- | --- |
| Cloudflare Pages | Статические файлы админки и адрес `*.pages.dev` |
| Браузер сотрудника | React, Refine Core, Ant Design; интерфейс и запросы к API |
| Серверная среда / Supabase | Аутентификация, проверка прав, бизнес-операции, база, закрытые файлы и фоновые задачи |

Для рабочей системы серверные данные и хранилище планируются в Казахстане. Это решение уточняет прежнее предложение размещать админку на том же VPS: её статические файлы размещаются на Pages. Прототип в облаке использует вымышленные данные.

## Бесплатный тариф и его границы

По документации Cloudflare, проверенной 2026-10-16, запросы к статическим файлам Pages бесплатны и не ограничены по количеству, если они не вызывают Functions. Сохраняются ограничения тарифа на сборки, количество файлов и размер отдельного файла; перед развёртыванием проверить актуальные значения по ссылке ниже.

Бесплатность статической раздачи не распространяется на серверные ресурсы, базу, хранение вложений, резервные копии или сторонние интеграции. При добавлении Pages Functions их квоты и тарификация рассматриваются отдельно. Условия провайдера могут изменяться.

## Требования реализации

- В сборке нет реестров жителей, закрытых документов, данных обращений и серверных секретов. Клиентские переменные Vite считаются публичными.
- Supabase publishable key допустим в браузере при корректных серверных проверках и RLS; service-role key, токен бота и OIDC Client Secret — только на сервере.
- Проверять права на сервере: доступность HTML/JavaScript не предоставляет доступ к данным ОСИ.
- Настроить SPA-маршрутизацию для открытия вложенных страниц по прямой ссылке и после обновления браузера.
- Настроить разрешённые origins, адреса возврата Supabase Auth и HTTPS. CORS не заменяет проверку полномочий.
- Preview-сборки не подключаются к рабочим данным и не получают производственные секреты; для Auth использовать отдельную тестовую среду и явно разрешённые адреса.
- Персональные данные не включаются в URL, статические файлы и журналы сборки. Внешний хостинг интерфейса не является автоматическим подтверждением соответствия всей системы требованиям к персональным данным.

## Альтернативы и последствия

Размещение статики на VPS в Казахстане остаётся технической альтернативой, но для интерфейса выбран Pages ради отдельного бесплатного хостинга и доставки статических файлов. Серверные полномочия и данные остаются независимыми от хостинга интерфейса.

Серверный рендеринг и Pages Functions сейчас не нужны. При появлении таких требований пересмотреть стоимость и границы размещения.

## Проверка при реализации

- Сборка Vite публикуется как статический сайт; основные действия работают на телефоне.
- Прямое открытие и обновление вложенных маршрутов не дают ошибку 404.
- Вход Telegram возвращает сотрудника на разрешённый адрес админки.
- Неавторизованный посетитель не получает данные через API или хранилище.
- В статической сборке отсутствуют серверные секреты и персональные данные.
