# ADR-007: адресные обновления инцидента и выбранные медиа публикаций

Дата: 17.10.2026. Реализация: VS-7, PR #17. Основание: EMG-03–07, PUB-01–03, NTF-01–03, ADR-003/006.

## Контекст

Охват аварии меняется во времени. Исправление ранее опубликованной информации должно доходить и до прежней аудитории. Принятый внутренний отчёт задания сам по себе не разрешает выдавать его файлы жителям. Завершение общей аварии не означает выполнения каждого локального задания.

## Решение

- Охват инцидента задаётся сочетанием объекта, услуги и зоны. Для части объекта указывается явный список помещений; название зоны без списка не расширяет аудиторию до всего дома.
- `broadcast` сохраняет неизменяемые текст и охват версии, продвигает курсор по person вместе с созданием существующего notification outbox. Порции ограничены; блокировка `skip locked` разделяет конкурентных обработчиков. Новый диспетчер Telegram не создаётся.
- При изменении охвата корректировка адресуется объединению старого и нового охвата. Перед доставкой повторно проверяется действующая связь получателя с помещением, режим `is_test` и доступность публикации. Служебные сигналы проверяют текущего ответственного и полномочия.
- Связи инцидента с обращениями и общими работами создают канонические `common_work_request` только для совпадающих домов. `incident_work_request` хранит происхождение автоматически добавленных пар. Такие связи снимаются через инцидент с дальнейшим маршрутом; ранее созданные вручную пары не удаляются. Передача результата использует проверки VS-4 и снимок ADR-006, не подтверждает результат за жителя.
- Для публикации отчёта сотрудник явно выбирает до десяти фото/видео из последнего принятого отчёта завершённой общей работы и подтверждает проверку приватности. Смена источника/вида сбрасывает выбор, редактирование сбрасывает согласование. При выпуске готовность и соответствие файлов проверяются повторно под блокировкой общей работы.
- `publication_attachment` — отдельное основание доступа к выбранному файлу через опубликованную карточку и PDP. Исходный бакет остаётся приватным, ACL исходного вложения задания не меняется. API выдаёт подписанную ссылку на 300 секунд. Уже выданная ссылка действует до истечения срока даже после отзыва связи; новые ссылки после отзыва/архивации не выдаются. Автоматического обезличивания содержимого нет — выбор требует проверки сотрудником.
- Публикации, требующие утверждённого документа, включая финансовые, блокируются до подключения утверждённых версий VS-8. Разрешение председателя отдельно сохраняется, но не заменяет документ.

## Альтернативы

Рассылка по всему дому для любой зоны нарушает адресность. Открытый Storage или изменение исходного ACL раскрывает внутренние файлы. Копирование всех вложений отчёта автоматически не гарантирует отсутствие персональных данных. Автоматическое закрытие связанных обращений обходит индивидуальную приёмку.

## Проверки

Модульные проверки FSM, PDP, охвата, отзыва служебного доступа и документального гейта; UI-проверки обязательного восстановления. Интеграционные сценарии сохраняются в Git; их исполнение отложено по действующему правилу AGENTS.md. До SQL-приёмки и сквозного прогона на тестовой среде ADR не является подтверждением готовности к эксплуатации.
