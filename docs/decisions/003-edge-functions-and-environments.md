# ADR-003: TypeScript, Edge Functions и разделение сред

Дата: 2026-10-16. Статус: принято пользователем; реализация и развёртывание не выполнены.

## Контекст и драйверы

Боту и кабинету нужны общие правила, права и данные. Пользователь предложил обработку webhook через Supabase Edge Functions на TypeScript. Рабочие данные должны размещаться в Казахстане; Supabase Cloud используется для прототипа с вымышленными данными. Нужны сохраняемые состояния диалогов, уведомления и задания по расписанию.

## Рассмотренные варианты

- Общий backend с отдельным фоновым процессом: удобен для длительных задач, но требует сопровождения отдельных процессов. NestJS был предложен, но не принят.
- Edge Functions с общими модулями, состоянием и очередью в PostgreSQL, обработкой по расписанию: выбран; сокращает число отдельных прикладных процессов, но требует учитывать пределы выполнения функций и обеспечивать повторы задач.

## Решение

- Серверный код — TypeScript и Supabase Edge Functions; общие бизнес-модули используются ботом и кабинетом.
- Бот принимает webhook Telegram; состояние диалогов хранится в PostgreSQL.
- Очередь и состояние заданий сохраняются в PostgreSQL; обработчики запускаются по расписанию. Обязательный отдельный постоянно работающий процесс обработчика из прежнего ARC-04 заменён этим решением.
- Прототип — Supabase Cloud с вымышленными данными и отдельными секретами. Реальные персональные данные и рабочие секреты туда не переносятся.
- Рабочая система — самостоятельно размещённый Supabase в Казахстане: функции, PostgreSQL, Auth, закрытое Storage. Серверная инфраструктура для неё требуется; провайдер и конфигурация ещё не выбраны.
- Статическая админка остаётся на Cloudflare Pages по ADR-002. Её рабочая версия обращается к рабочему API/Auth; прототип не подключается к рабочей среде.

## Последствия и ограничения

Бесплатные квоты Cloud не подтверждают бесплатность всей системы и не распространяются автоматически на рабочую инфраструктуру. В списке регионов Cloud нет Казахстана. Поддержка self-hosted функций документирована, но переносимость конкретного приложения ещё предстоит проверить.

Общие модули сохраняют единую модель прав; функции являются точками входа, а не независимыми микросервисами. Нужны проверки подлинности webhook, защита от повторов, серверная авторизация и надёжные повторы фоновых заданий. Конкретные контракты очереди, функции расписаний, лимиты ресурсов, импорт Excel и обработка файлов проектируются отдельно. Развёртывание не выполнено.

Согласованные ручные копии пилота, RPO/RTO и проверка восстановления сохраняются по OPS-03. Авторизация и TOTP сохраняются по ADR-001.

## Проверки при реализации

- Бот и кабинет используют одинаковые правила и проверяют актуальные полномочия.
- Повторная доставка webhook не создаёт повторную операцию.
- Диалог продолжается после завершения вызова функции.
- Задания не теряются при ошибке функции; повтор не дублирует бизнес-операцию.
- Функции, Auth и расписания проверены в самостоятельно размещённой рабочей среде.
- Прототип и preview не имеют доступа к рабочим данным и секретам.
