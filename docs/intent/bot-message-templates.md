# Намерение: раздел «Шаблоны» — декларативная настройка текстов Telegram-ботов

- Дата: 2026-10-18
- Статус: подтверждено владельцем проекта в интервью (этап перед спецификацией)
- Далее: спецификация (`docs/specs/bot-message-templates.md`), затем план и срезы

## Суть

Все тексты двух Telegram-ботов — ответы диалогов и уведомления вне диалога —
становятся именованными шаблонами с переменными в `{}`, версионированием и
вариантами ru/kk. Администратор управляет ими из нового раздела «Шаблоны»
кабинета: поиск, каталог переменных, предпросмотр, сохранение как новая
версия, откат. Без правки бот использует встроенный дефолт из кода.

## Зафиксированные решения интервью

| Вопрос | Решение |
| --- | --- |
| Охват | 1) ответы бота в диалогах (сценарии, `/help`, ошибки), 2) уведомления вне диалога (`LocalizedNotice`). Подписи кнопок и описания команд меню Telegram — нет |
| Версионирование | Append-only: каждое сохранение — новая неизменяемая версия, активна последняя, откат = выбор прошлой версии активной. Прецедент — `time_rule_version`. Начатые диалоги не прилипают к старой версии |
| Кто редактирует | Председатель / администратор / техадмин — privileged-действие PDP (по образцу `registry.rules.edit`), аудит в `audit_log` |
| Переменные | Подстановка `{имя}`; каталог переменных с описаниями и примерами; условная логика и склонения — вне среза |
| Языки | ru и kk; рендер — один язык по профилю получателя (как сейчас) |
| Эмодзи | Разрешены — это обычный текст |
| HTML | Только разрешённый Telegram набор тегов; значения переменных всегда экранируются (`esc()`); действует существующий каскад отправки HTML → без разметки |
| Дефолты | Живут в коде (каталог шаблонов); в БД — только переопределения. Обновление кода улучшает тексты, не затёртые администратором |

## Формулировка намерения

- **Результат:** раздел «Шаблоны» в кабинете — декларативное управление всеми
  текстами ботов жителей (`@munar_tau_bot`) и сотрудников
  (`@munar_tau_worker_bot`) через именованные шаблоны.
- **Пользователь:** редактируют председатель, администратор, техадмин
  (privileged-действие PDP, аудит в `audit_log`); тексты получают жители и
  исполнители.
- **Зачем сейчас:** правка формулировок и эмодзи без релиза кода.
- **Успех:** администратор находит шаблон по разделу/поиску, видит каталог
  переменных с описаниями, редактирует ru и kk, смотрит предпросмотр с
  примерными данными, сохранение = новая версия, возможен откат; без правки —
  встроенный дефолт из кода.
- **Ограничение:** бизнес-правила, FSM и PDP-разрешения не меняются; рендер —
  один язык по профилю; эмодзи разрешены; HTML-теги — разрешённый набор
  Telegram; версии неизменяемы, активна последняя.
- **Вне среза:** подписи кнопок, описания команд в меню Telegram, условная
  логика и склонения в шаблонах, поле «Сигнал проверяется» (VS-7, хранимый
  `public_text` инцидента).
