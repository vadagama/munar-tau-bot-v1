# VS-7: реализация и проверка

17.10.2026. Ветка `feature/vs-7-incidents-publications`, [PR #17](https://github.com/vadagama/munar-tau-bot-v1/pull/17). Функциональная реализация представлена на ревью; полная приёмка не заявляется.

## Реализованные сценарии

| Требования | Поведение |
| --- | --- |
| EMG-01/02, JOB-04 | Основной/резервный дежурный, администратор, график и телефон; сигнал из обращения/задания; принятие только текущим ответственным; явное назначение при отсутствии смены. |
| TIM-05 | 10 календарных минут до резерва, ещё 10 до администратора; уведомление руководства, без имитации принятия/выезда. |
| EMG-03–06 | Проверка сигнала, подтверждение/опровержение, устранение, проверка восстановления, завершение/возобновление; обязательные основания, фактические даты, прогноз и следующее обновление. |
| EMG-04/05, NTF | Объект/зона/услуга, частичное восстановление, ограничения, курсорная адресная рассылка через существующую очередь; повторная проверка получателей, резервный маршрут недоставки. |
| EMG-07 | Привязка с проверкой места/причины, отсоединение с дальнейшим маршрутом; индивидуальная передача результата через проверки VS-4, причины неготовности, без закрытия за автора. |
| PUB-01–03 | Объявления, отчёты принятых работ с явно выбранными медиа, согласование, планирование, архив; предпочтения/дайджест; связанное обращение о проблеме. |
| Плановые отключения | Плановые даты, услуга, ответственный, обновление плана; фактическое восстановление подтверждается отдельно. |
| FIN, VS-8 | Согласование председателем сохраняется. Финансовые и документозависимые публикации блокируются до интеграции утверждённых документов VS-8. |

Операции общие для API, бота и эмуляции. Сервер проверяет PDP, область, `is_test`, версию и повтор операции. Миграция аддитивная, журналы append-only, прямой доступ anon/authenticated закрыт. Контракт файлов/аудитории — [ADR-008](decisions/008-vs7-audience-and-publication-media.md).

## Выполненные проверки

- `npm run lint`, `npm run typecheck` — успешно.
- `npm test` — 309 тестов ядра и 35 тестов кабинета успешно.
- `npm run build -w admin`, проверка сборки на секреты — успешно. Vite сообщает о размере общего JS-чанка; разбиение и нагрузочная приёмка не выполнены.
- `deno task check`, `deno task lint`, `deno task test` — успешно, 41 тест функций.
- Браузер на localhost, реальные компоненты с временным транспортом фикстур: список/карточка аварии, частично восстановленный охват, обязательные поля завершения; опубликованное отключение после планового срока сохраняет «не подтверждено». Это проверка интерфейса, не сквозная проверка с БД. Временная страница не входит в продукт.
- Независимое ревью: устранены ошибки назначения необработанных сигналов, голодания напоминаний, связи работ другого дома, приватности выбранных медиа и повторной проверки служебных получателей.

## Не выполнено и почему

- SQL-миграция, интеграционные и конкурентные сценарии **не запускались**: действующее AGENTS.md запрещает агенту запуск интеграционных тестов без отдельного явного запроса. Тесты сохранены в `source/core/tests/integration/incidents.test.ts`; они не считаются пройденными.
- Реальный Telegram, фоновые jobs облачного стенда, Storage и сквозной вход с ролями не проверялись. Демонстрационный стенд не обновлялся.
- Цели производительности пользователь оставил на последующее согласование 17.10.2026. Нагрузочный тест не выполнялся; ранее предложенные значения не являются принятыми нормативами.
- Документальная приёмка FIN/PUB зависит от VS-8; блокировка является намеренной границей этого среза.

## Воспроизведение полной приёмки после разрешения SQL-тестов

Использовать исключительно Sydney и существующий session advisory lock. Сначала проверить повторное применение миграций, RLS и append-only. Затем проверить несколько получателей/помещений, отзыв связи между fanout и отправкой, повторный/параллельный jobs, две десятиминутные эскалации и гонку с принятием. Проверить два дома с разными работами, возврат индивидуального результата, частичное восстановление, неготовое локальное задание, архив публикации перед отправкой и возврат работы перед выпуском. После этого пройти сценарии требований §15.2 и процессов §8 с тестовыми персонами. Нагрузочный прогон выполняется после утверждения целей.

## Команды бота / эмуляции

- `/emergency КОД_ДОМА` — телефон и предупреждение, доступно до подтверждения регистрации.
- `/emergency НОМЕР_ОБРАЩЕНИЯ описание` — возможная авария в доступном обращении.
- `/danger НОМЕР_ЗАДАНИЯ описание`; для общей работы нескольких домов: `/danger НОМЕР_ЗАДАНИЯ КОД_ДОМА | описание`.
- `/signals`, `/acceptsignal ID ВЕРСИЯ` — срочные сигналы и принятие.
- `/incidents`, `/incident НОМЕР` — доступные инциденты.
- `/publications`, `/publication ID` — доступные публикации.
- `/workproblem ID_ПУБЛИКАЦИИ КОД_ДОМА | описание` — новое связанное обращение.

В эмуляции выбрать сценарий «Аварии и публикации»: сообщения остаются в simulator, наружная отправка не выполняется.
