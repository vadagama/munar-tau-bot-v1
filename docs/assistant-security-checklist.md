# ИБ-чеклист AI-ассистента (до реальных данных)

Статус: черновик для ИБ-анализа (условие 2 ADR-021). Пилот идёт на вымышленных
данных; реальные данные — только после закрытия открытых пунктов и отдельного
решения. Составлен в S6.2; открытые пункты перечислены явно в конце.

## Потоки данных к провайдеру (DeepSeek)

За один ответ модели уходят:

- **Вопрос сотрудника** (свободный текст) и **текст ответа модели**.
- **JSON-выводы read-only инструментов** (S2.1/S4a.2): номера и названия
  обращений/заданий, описания до 800 символов (`cut`), состояния (готовые
  подписи ru/kk), адреса (метки помещений), ФИО и телефоны (e164) жителей
  из `search_residents`, исполнители, агрегаты `/v1/reports/*` (числа).
- Системный промпт: языковая инструкция (S6.2) и описания инструментов.

**Не уходят к провайдеру и не попадают в транскрипт:** JWT пользователя,
ключ провайдера, файлы и вложения, пароли/токены, схемы БД, другие таблицы
кроме выводов инструментов. Ключ живёт только в памяти изолята
(`POST /v1/assistant/runtime-token`), JWT — тоже в памяти изолята.

Ограничения контура: модель видит только данные, которые вернули инструменты
белого списка под PDP — ровно те, что сотрудник и так видит в кабинете.
Разговор не пишется в PostgreSQL, дублирования нет.

## Хранение и журналирование

| Где | Что | Ретеншн |
| --- | --- | --- |
| SQLite Durable Object (`pi_*`-таблицы) | Транскрипты диалогов (вопросы, ответы, выводы инструментов) | S6.1: старая эпоха стирается через сутки после границы 05:00 + `ASSISTANT_RETENTION_DAYS` (по умолчанию **7 суток — предложено, утвердить**); текущая эпоха живёт до следующей границы |
| Cloudflare Workers observability | Structured-логи изолята: имена инструментов, длительности, исход (`ok`), события teardown — **без ПДн и текстов** | Настройки Cloudflare (см. открытые пункты) |
| PostgreSQL (ledger) | Учёт расхода: `operation_id`, токены, суммы — идемпотентно (S3.1) | По правилам ledger |
| PostgreSQL (аудит API) | Журнал `/v1`-чтений под PDP — существующий аудит API | Существующий |

Транскрипты лежат в Cloudflare DO, то есть **вне Казахстана** — резидентность
входит в открытые пункты.

## Провайдер: журналирование, обучение, opt-out

- Пункты «проверить на дату анализа»: (1) включено ли журналирование запросов
  на стороне DeepSeek и его срок; (2) режим обучения на данных API
  (training opt-out) и как он гарантирован договором/настройками; (3)
  обработка данных в КНР — применимые требования локализации/передачи.
- `base_url` провайдера уже настраивается из runtime-token: замена DeepSeek на
  любого OpenAI-совместимого провайдера (например, self-hosted vLLM в Казахстане)
  не требует изменений кода ассистента.

## Резидентность и размещение рантайма

Вариант A (текущий): Cloudflare Workers + DO — данные транскриптов вне РК.
Вариант B: self-hosted рантайм (vLLM в Казахстане) — решается ИБ-анализом
(ADR-021, условие 2). Код ассистента к провайдеру ходит по настраиваемому
`base_url`, смена варианта не меняет логику чата.

## Реализованные меры (проверяются тестами, если не указано иное)

- **Доступ к данным только через `/v1` с JWT самого пользователя** (PDP на
  стороне API); у ассистента своего доступа к БД нет (ADR-021).
- **Read-only guard**: `beforeTool` блокирует любой вызов вне белого списка
  read-only реестра; решение только по имени — инъекция инструкций из данных
  (LLM01) не выводит за контур; инструменты записей нет.
- **Ответ модели — недоверенный ввод**: панель рендерит только виджеты из
  JSON (карточки-ссылки, таблицы), HTML/script из ответа не исполняется (S4).
- **Гейт**: JWT (ES256 по JWKS) + `enabled` + сверка профиля и эпохи; лимиты
  день/месяц до submit; kill switch (`enabled=false` — серверно для всех).
- **Ключ провайдера** — только в памяти изолята, выдаётся включённому профилю
  по runtime-token; **JWT не в URL** (первое WS-сообщение), сокет без auth
  закрывается через 10 с.
- **Харденинг S6.1**: проверка эпохи на хендшейке — DO прошлой эпохи не отдаёт
  историю даже с валидным JWT; retention старых эпох (teardown-задача +
  ленивый fallback); метрики tool-вызовов без персональных данных.
- **Идемпотентность** submit/учёта по `operation_id`; лимиты `page_size` ≤ 20;
  дружелюбные отказы вместо стеков.
- **Эмуляция исключена**: в эмуляции ассистент выключен сервером; test-персоны
  не имеют доступа (ADR-021).

## Открытые пункты (перечислены явно — приёмка S6.2)

1. **Training opt-out и журналирование DeepSeek** — подтвердить актуальное
   состояние политики провайдера на дату анализа; зафиксировать требование в
   договоре (не хранить, не обучать).
2. **Резидентность транскриптов** — решение Cloudflare (вне РК) против
   self-hosted vLLM в Казахстане; влияет на требование о локализации ПДн.
3. **Классификация ПДн в контексте ассистента** — какой объём персональных
   данных (ФИО/телефоны жителей в выдаче `search_residents`) допустимо
   передавать модели в пилоте; при ограничении — маскирование в инструментах.
4. **Retention логов наблюдаемости Cloudflare** — период хранения и доступ,
   проверить настройки на дату анализа.
5. **Retention `pi_*` — 7 суток** — предложено в S6.1, утвердить у владельца
   продукта; при изменении — env `ASSISTANT_RETENTION_DAYS` без кода.
6. **Данные в бэкапах Cloudflare DO** — уточнить, попадает ли SQLite DO в
   бэкапы платформы и как формулируется удаление.
7. **Prompt-injection из полей данных** — guard закрывает инструменты, но
   текст ответа модель строит сама: периодический контроль качества ответов
   на инъекции из данных (процедурная мера, владелец — ОСИ).
