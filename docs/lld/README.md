## Как читать

- LLD не расширяет HLD и модель процессов: состояния, переходы и права берутся из них дословно. Расхождение между документами — ошибка; приоритет у модели процессов, затем HLD, затем LLD.
- «Точка решения» — место, где выбор влияет на контракт или схему и требует явного согласования (вопросы задаются по мере влияния на конкретное решение).

## Связь с ADR-003

ADR-003 (принят 2026-10-16) определяет исполняемую среду: TypeScript + Supabase Edge Functions; состояние диалогов и очередь — в PostgreSQL; обработчики запускаются по расписанию; прототип — Supabase Cloud с вымышленными данными; рабочая среда — self-hosted Supabase в Казахстане (провайдер отложен до этапа развёртывания, требование размещения сохранено). LLD построен в этих рамках:

- три функции-входа: `bot-webhook`, `api`, `jobs` — вместо отдельного постоянно работающего процесса;
- всё «само происходящее» — таблицы `job_queue`, `outbox`, `timer`, обрабатываемые по расписанию;
- пределы времени вызова функции учитываются: длинные задачи делятся на возобновляемые шаги (раздел [фоновых задач](04-background-tasks.md));
- shared-модули ядра общие для бота и кабинета, функции — только точки входа.
