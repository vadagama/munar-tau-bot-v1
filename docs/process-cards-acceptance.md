# Карточки процессов: стандарт и приёмка

Дата: 22.10.2026. Требования: UI-01, REQ, WRK, REG, EMG, NTF; правила переходов — `request-lifecycle.md`, права — ADR-013/014/016. Направление согласовано пользователем: применить ко всем карточкам процессов.

## Стандарт

1. Шапка сохраняет идентичность объекта. Общий CardDrawer разворачивается в доступную ширину без перемонтирования форм.
2. Перед содержимым — «Сейчас по процессу»: состояние, ожидаемый участник, срок Алматы, объяснение следующего шага. Ожидание другого участника не заменяется фиктивной операцией.
3. Одно доступное основное действие, частые альтернативы, раскрываемые остальные действия. Исходные обработчики, disabled, проверки версий и PDP сохраняются. Недоступный переход не создаётся подсказкой.
4. Содержание и материалы оформляются общими DetailSection. Перед подтверждением операции форма объясняет её последствия. После операции сохраняются существующие перечитывание и защита черновиков.
5. История раскрывается явно. Состояние раскрытия сбрасывается при смене записи, но не при фоновом чтении той же записи.
6. Нет общего линейного степпера: повторное рассмотрение, уточнения, приостановки и доработка не являются прямой линией.

## Матрица применения

| Объект | Следующий шаг | Материалы и особенности |
| --- | --- | --- |
| Обращение | Новое → рассмотрение; заявка на рассмотрении → работа; вопрос/жалоба → итоговый ответ или задание; уточнение → ожидание автора; отложено → явное возобновление; результат → подтверждение автора; доработка → новый объём | Процесс до информации; связанные задания кликабельны; при незавершённых заданиях предлагается их проверка; переписка и история ниже. Последствия переходов поясняются в форме |
| Задание | Назначение → принятие исполнителем → начало → отчёт → независимая проверка → приёмка/доработка | Информация и инструкция разделены; на проверке отчёты идут первыми, текущий перед предыдущими, решение после текущих материалов, предыдущие версии раскрываются отдельно. Управляющий не начинает работу вместо исполнителя. Историческая просрочка на завершённом задании не считается текущей |
| Общая работа | Создать задания → проверить выполнение → явно завершить | Связанные обращения и задания отдельно; приёмка общего объёма не подтверждает результат за жителей |
| Авария | Проверить сигнал → устранение → проверить восстановление | Главный переход выбирается только из серверного `actions`; неуспешная проверка и обновление доступны рядом. Следующее обновление имеет собственный срок |
| Публикация | Подготовить → опубликовать/запланировать; финансовый отчёт → согласование председателя | У другого сотрудника нет фиктивной кнопки согласования; после сохранённого `approved_by` предлагается публикация вместо повторного согласования; отключение требует отдельного подтверждения восстановления; история свёрнута |
| Анкета | Проверить данные/совпадения → решение; запрос уточнения, отказ и спор — с основанием | Перед формой показаны цель, состояние и последствия. Исправление/удаление имеют собственное пояснение |
| Недоставка | Связаться → записать результат контакта | Завершение контакта не означает прочтение или согласие с результатом работ |
| Регулярные запуски и ручной запуск шаблона | Проверить исполнителя/срок/период → сохранить или запустить | Начатые задания не меняются автоматически; каждый запуск создаёт отдельные объекты |
| Восстановление Telegram | Проверить личность и новую анкету → перенос привязки | Объясняется прекращение прежних сеансов и сохранение человека/ролей/истории |
| Сотрудник | Проверить полномочия и открытые обязанности → изменение ролей | Обязанности требуют явной передачи; редкое прекращение полномочий раскрывается отдельно |

Редакторы справочников, настроек и каталога сообщений не получили искусственных этапов процесса. Формы создания сохраняют собственные названия и подтверждения, не показывают состояние несуществующего объекта.

## Ограничения и права

Подсказки — отображение текущего процесса, а не отдельный автомат переходов. Все записи идут через прежние серверные операции. Проверки доступа, версии, аудит, независимая приёмка и аудитории файлов не менялись. Неизвестное состояние получает нейтральное объяснение без рекомендации перехода.

Старый API карточки обращения не отдаёт `is_required` у связанных заданий. Поэтому при отсутствии этого признака незавершённая запись консервативно предлагается к проверке, без утверждения её обязательности. Отправка итогового ответа остаётся среди прочих доступных операций с серверной проверкой; интерфейс не объявляет обязательства выполненными по одному списку.

Формы расписания используют прежний ввод даты во времени устройства, с явным пояснением; сводные сроки отображаются в Алматы. Внешняя выкладка и интеграционные БД-тесты не выполнялись.

## Проверка

- Unit-тесты: роль автора/управляющего/исполнителя, ожидание другого участника, приёмка собственного отчёта, ограничения рекомендаций аварий серверным списком, согласование председателем, неизвестное состояние.
- Компонентные тесты: одно главное действие, раскрываемые прочие, сохранение disabled/обработчиков, свёрнутая история; разворачивание без потери текста.
- Регрессия форм: прежние POST, версии, причины, приёмка доказательств и защита черновиков.
- Браузер: обращение на рассмотрении, форма начала работы и возврат без записи; авария на проверке восстановления; карточка задания и разворачивание.
- Пройдены 222 теста кабинета, admin typecheck, общий lint, admin build и secret scan. После уточнения проверки предыдущих версий отдельно пройдены 27 тестов заданий. Предупреждения сборщика о размере общего chunk и React Router о будущих флагах v7 — прежние; новых ошибок приложения не обнаружено.

Кнопки, размещённые непосредственно в «Сейчас по процессу» (включая «Проверить задания» общей работы), имеют ширину по содержимому и не растягиваются поперёк карточки; максимальная ширина ограничена контейнером. Проверено в браузере: 164 px при ширине блока 1264 px; компонентные тесты процесса и страницы общих работ проходят.

## Шаблоны сроков (UI-01, 23.10.2026)

Под полями сроков в обращениях (начало работы, следующее действие), заданиях
(создание, исправление, приостановка), общих работах, ручном запуске шаблона задания,
следующем обновлении инцидента и плановом окончании отключения доступны кнопки:
«час», «2 часа», «3 часа», «6 часов», «12 часов», «сутки», «неделя», «месяц».
Срок отсчитывается от момента нажатия; месяц — календарный с ограничением
последним днём следующего месяца. Кнопки переносятся на новую строку при
недостатке места. Дата остаётся доступна для ручного ввода; выбор шаблона
проходит обычные проверки формы и учитывается как изменение.
Фактические даты, начало периода, время публикации и расписание запусков
сохраняют прежние поля.

Проверки: `deadline-input.test.tsx` покрывает все интервалы, момент повторного
нажатия, конец месяца и високосный год, ручной ввод и отправку формы,
совместимость с DatePicker и блокировку формы.

Локально: 234 теста кабинета, TypeScript, ESLint и production-сборка прошли.
Форма «Начать работу» проверена в браузере на изолированных данных: выбор
«6 часов» заполняет дату, кнопки расположены сразу под полем, консоль без ошибок.
